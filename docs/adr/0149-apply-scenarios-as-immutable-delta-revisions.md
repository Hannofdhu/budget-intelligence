# 候选应用创建差异组件版本并保留非杠杆输入

可行候选由数据维护人员显式应用到当前草稿。应用命令必须在一个数据库事务中锁定当前修订，复核候选来自该修订的 `OPTIMAL` 求解运行且输入指纹未变化，校验每条差异的原值、建议值、调整量和内容哈希，然后创建新的差异组件版本、预算修订、应用记录和审计事件。候选、来源修订和结果修订均保留，不原地覆盖。

入口结构变化会生成新的入口明细版本。计划新生人次不是自动调平杠杆，因此系统只将原人数、原因、锁定值和锁定状态重挂到新入口明细 ID；不得随候选增减。若入口变化只发生在同一校区内部，沿用原校区入口确认；若改变任一校区合计，则生成新的校区入口版本，并要求部门预算负责人重新确认。

比例候选只能使用已确认边界内、符合 100 ppm 步长且未锁定的值，新比例版本继承原边界确认的来源链。折扣候选只能使用与求解运行绑定且仍有效的折扣解锁，按 1,000 ppm 步长生成新折扣版本及派生参数确认。上述继承只证明候选在既有授权边界内，不构成部门预算负责人的正式方案确认。

新修订必须移除旧人数、班均、收入、目标闭合、求解运行、折扣解锁和正式确认引用。完整复算、正式方案确认和发布仍是后续独立动作；候选应用成功本身不表示预算已闭合或可发布。
