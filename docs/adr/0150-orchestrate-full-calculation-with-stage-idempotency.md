# 完整计算作业采用固定顺序和阶段级幂等重放

候选应用创建新不可变修订时，必须在同一数据库事务登记 `CALCULATE_BUDGET_REVISION` 作业，避免修订已经提交但计算消息丢失。数据维护人员也可以通过当前修订的显式计算接口登记同类作业。作业载荷固定 `phase1-full-calculation-v1`，只包含修订和执行身份等控制信息，不包含业务明细、来源凭据或运行时默认规则。

Worker 固定按“人数、班均、收入、目标闭合”顺序执行。每个阶段从作业 ID 派生独立、稳定的幂等键，并使用上一阶段产生的新修订作为下一阶段输入。Worker 在任一阶段提交后中断时，重试同一作业会重放已经完成的阶段响应，再从未完成阶段继续，不重复写入业务结果。

业务前置条件不足标记为 `INCOMPLETE`，与代码异常导致的 `FAILED` 分离。候选改变校区入口合计但负责人尚未确认时，作业使用 `CAMPUS_ENTRY_CONFIRMATION_REQUIRED` 暂停；确认完成后重新排入同一作业。完整计算成功并不自动执行正式方案确认或发布，最终仍以目标闭合、全部硬约束和部门预算负责人的独立正式确认为准。
