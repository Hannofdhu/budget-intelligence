# 正式方案在完整复算通过后落确认，发布保持独立

部门预算负责人执行“正式方案确认”时，系统先为当前修订登记 `FORMAL_CONFIRMATION` 用途的完整计算作业。Worker 仍按人数、班均、收入、目标闭合的固定顺序复算；只有最终目标闭合结果及全部发布硬约束通过，才创建新的不可变确认修订和 `formal_plan_confirmation`。复算缺少输入或仍有缺口、超额、不可成班、确认缺失等阻断时，作业进入 `INCOMPLETE`，不得留下半生效的正式确认。

正式确认摘要必须冻结发布检查结果、完整输入指纹以及每条计划新生人次的完整维度、人数、原因和锁定状态。确认记录不可更新或删除；任一上游命令生成新修订时，通过修订清单移除 `formal_confirmation_id` 使旧确认自然失效，旧记录继续保留审计。

发布是负责人执行的第二个独立命令。发布事务重新计算发布输入指纹并复核全部硬约束，只接受当前草稿中精确绑定的有效正式确认；通过后追加 `PUBLISHED` 与 `CURRENT_POINTER_MOVED` 生命周期事件，并原子移动年度预算的当前发布指针。发布不复制业务明细，预算修订本身就是不可变年度预算基线；系统不提供强制发布、忽略阻断或扩大容差路径。
