# 一期采用模块化单体、独立计算进程和 PostgreSQL 作业队列

年度预算一期采用一个代码库和一个业务数据库，按预算版本、参数、计算、调平、权限审计等模块划分边界；HTTP API 与计算 Worker 作为两个进程部署。长耗时计算通过 PostgreSQL 作业表和 `FOR UPDATE SKIP LOCKED` 领取，不在一期引入微服务、Kafka、Redis 或额外工作流平台。

该方案牺牲独立横向扩展能力，换取事务一致性、版本追溯和较低运维复杂度。模块之间只通过已定义的应用服务和领域事件接口交互，未来确有负载或组织边界时再拆分进程或服务。
