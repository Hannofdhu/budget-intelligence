# 期初老生：最终交付说明

日期：2026-09-08。状态：本地实现和隔离验收完成，未操作线上 BI、未发布业务预算。

## 适用范围

FY27 保留已定版 Excel 历史基线，不从 BI 重建、不重算替换、不回写。真实 BI 适配器拒绝 FY27 及以前的抽取请求；既有冻结历史仍可读取和回放。

FY28 起，以上一财年春季普通 `招生人次` 为来源，不使用 `招生人次(三分之二出勤口径)`。仅汇总标记为“数据”的实际记录。缺失值不是零；负数、非整数、未知实际标记和不完整维度阻断。来源保留快照、批次、分区、数据集和内容哈希。

## 计算与调平

- 来源七年级升八年级，八年级升九年级。原九年级毕业退出；八年级地理、生物退出。赛道、产品、科目、校区保持一致，源年级和目标年级分别保留。
- 第一季老生理论值为来源招生人次乘已绑定的春续暑续班率。按原有赛道/校区/季度最大余数法取整，不提前逐行四舍五入。后续季度按上一季整数总人次续班，仍留在同一预算明细。
- FY28 内核规则为 `phase1-headcount-opening-v2`。来源或版本缺失时不能回退首季老生为零。
- 调平沿用已确认顺序：固定入口总值内调整结构，续班率和新生占比等百分点并列推进，触界退出，最后才按原有授权进入折扣阶段。期初人数随候选春续暑续班率重算，既有锁定和确认边界照常生效。
- 精确枚举、CP-SAT 入口阶段、业务比例阶段、折扣阶段和候选全量复算均承接期初输入。保留规模限制、硬超时、64位范围证明、0.1个百分点折扣步长和0.05个百分点综合折扣容差；未完成不冒充不可行。

## 版本、应用与发布

期初版本为不可变记录。必须引用当前预算同部门冻结来源、当前组合版本和比例版本；来源汇总逐键逐值核对，目标组合由来源映射或显式零无重复地完整覆盖。旧快照缺少普通招生汇总时阻断，不回填冻结历史。

手工替换比例或组合后，旧期初绑定失效，须重新生成核验。候选应用由系统在同一事务重建期初版本：保留来源，绑定新比例 ID，更新人数与哈希，记录父版本。旧结果和确认失效；Worker 重算四阶段。撤销追加修订，恢复应用前的期初与比例版本，不删除历史。

正式确认和发布时，期初检查核验版本依赖、来源核验标记、v2规则以及人数输入指纹；其他发布门禁继续执行。收入达标或计算作业成功本身不等于已发布。

## API 与使用

1. 建立并冻结 FY28 来源，完成组合和比例版本维护。
2. `POST /api/v1/revisions/{revision_id}/opening-students`：提交来源组件 ID、上财年春季、完整来源明细及对应续班率 ID、显式零组合 ID和原因。需要数据维护权限、`If-Match`、`Idempotency-Key`。
3. `GET /api/v1/opening-student-versions/{id}`：同部门读取不可变版本及核验依据。
4. `POST /api/v1/revisions/{revision_id}:calculate`：Worker 自动按财年选择规则。直接调用人数 API 时显式指定 `phase1-headcount-opening-v2`。
5. 使用现有优化运行、候选应用、撤销、正式确认和发布 API；无需额外期初审批环节。

审计页和归档包含期初版本。本轮未新增独立图形化填报页面；维护入口为上述已验证 API，现有计算、审计和版本流程继续使用。
