## 操作路径

1. 本地 API、数据库和 Vite 启动后，打开期初维护页面，填写隔离合成预算修订 ID、对应部门和数据维护人员 ID。
2. 读取维护数据，核对来源名称、快照日期、分区、批次和指纹。多个来源时必须人工选择。
3. 按校区、科目或产品筛选，查看来源年级、续入年级、招生人次、春续暑续班率及理论老生人次。
4. 九年级毕业，八年级地理、生物结束，不续入；其他来源按升年级规则映射。人数最终取整留给正式计算。
5. 对无来源覆盖的每条明细明确勾选期初为零。未勾选就是缺失，不自动补零。
6. 填写原因后保存，系统核验冻结人数、绑定和全量覆盖，生成不可变版本及新修订。页面随即切换新修订；旧计算、正式确认失效。
7. 进入版本审计核阅，再按既有流程计算。保存期初版本不等于发布预算。

## 防护

- 冻结来源人数只读，不能直接修改计算后的期初老生人数。
- 缺失/无效人数、找不到唯一续班率绑定、未确认显式零、非当前草稿不能保存。
- 旧期初版本的依赖有效性由服务端复用正式人数加载校验。
- 保存使用 If-Match；相同请求重试保留幂等键，内容变化换新键。
- API 保留部门隔离、数据维护人员角色、FY27 阻断和不可变修订校验。
- 页面身份头只是现有本地开发机制，不是生产认证方案。
