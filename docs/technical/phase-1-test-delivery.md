# 第一期测试、验收追踪与交付计划

## 1. 质量门槛

一期不是“页面能算出数字”即完成。发布前必须同时证明：

1. 业务公式和离散规则与冻结规格一致；
2. 相同输入跨重复运行得到同一结果哈希；
3. 版本、确认、权限、失效和审计不可绕过；
4. 96 项业务验收均有可执行证据；
5. FY27 规模下达到容量目标，且没有通过降级业务约束换性能；
6. Excel 初始基线、系统计算和差异说明可追溯。

合并到主干前运行快速单元与契约测试；每日运行 PostgreSQL 集成和完整黄金样例；候选发布版本运行全量验收、并发、故障恢复、性能和安全测试。

### 2.1 单元测试

按纯函数边界覆盖：

- 历史率先汇总分子分母再相除、分母为零、小样本去校区回退；
- 入口范围优先级和完整维度匹配；
- 校区建议、无历史预留、新产品两段预留和最大余数；
- 续班关系、来源行留存、反推型与定量型新生分支；
- 分组最大余数、固定整数保留、精确余数同值的稳定 ID 决胜；
- 班均三态和四季全零；
- 含税转换、当季确认、跨季结转、第一季期初和下一财年甩出；
- 综合折扣原价收入加权、分母为零和完整精度容差；
- 三目标正负一万元边界、禁止跨赛道抵消；
- 对称贡献归因、字典序指标、候选去重和结果哈希。

每个稳定校验码至少有一个通过和一个失败测试；错误测试同时断言 `scope_key` 和 `repair_route`，不能只断言文案。

### 2.2 性质测试

使用生成式数据验证跨大量组合始终成立的不变量：

1. 最大余数结果均为非负整数，组内合计等于理论合计的 `ROUND_HALF_UP` 整数；
2. 入口明细合计等于校区确定值，校区合计等于锁定财年入口总值；
3. 修改显示名称或输入行顺序不改变分配、候选和结果哈希；
4. 取整尾差只分配给可调行，定量新生永不被改写；
5. `current_recognized + cross_season = net_of_tax_base`，误差只能来自明确的六位小数量化且有追踪；
6. 年度总结转等于四季季度总结转之和，末季甩出不重复计入本财年；
7. 对称归因中 `retention_contribution + new_share_contribution = R11 - R00`；
8. 预算修订和已发布结果永不原地更新；
9. 同一幂等键相同载荷不重复创建修订，不同载荷必冲突；
10. 任一上游组件哈希变化都会改变计算输入指纹并使依赖的确认失效。

性质测试固定随机种子，失败时保存最小化后的输入夹具；种子和夹具进入 CI 产物。

### 2.3 黄金样例

黄金样例不是复制 Excel 计算结果后永久相信，而是保存“输入快照＋规则版本＋预期明细＋差异说明”。首批至少包含：

- FY27 学校版完整代表性子集，覆盖智慧伴学、智慧空间、四季、入口/非入口、普通/白金/云帆/THINK/高端小班；
- Excel 已明确的四季含税转换和结转公式；
- 1.06 转换、期初结转和下一财年甩出边界；
- 新产品预留、无历史校区、同余数尾差；
- 反推新生、锁定人工计划 0/正整数、班均临界值；
- 缺口、超额、入口阶段可行、比例阶段可行、折扣解锁后可行和精确不可行。

黄金文件使用规范 JSON 和 SHA-256，不保存花名册明细或个人信息。若 Excel 导入工具对公式返回 `#NAME?` 或 `#VALUE!`，保留原公式并使用兼容 Excel 的计算引擎或经核验的有界公式验证；不得把导入器错误当成业务预期值。

任何黄金结果更新必须同时提交：规则或实现变更说明、前后差异、对应 ADR/验收 ID、复核人。无解释的批量重录快照禁止合并。

### 2.4 契约测试

- OpenAPI 请求和响应与 DTO 版本一致；
- 金额必须是十进制字符串、ppm 和整数人数不能接受浮点 JSON；
- 稳定错误码、HTTP 状态和修复入口符合契约；
- `If-Match`、`Idempotency-Key` 缺失时拒绝写命令；
- 观远来源适配器只接收字段白名单，宽表查询只绑定唯一最新 `dtdate`；
- 文件存储适配器本地实现和生产实现通过同一契约套件。

契约有破坏性变化时增加 `/api/v2` 或兼容字段，不能悄悄改变已有字段含义。

### 2.5 PostgreSQL 集成测试

使用真实 PostgreSQL，不用 SQLite 替代以下行为：

- 不可变组件版本、唯一键、外键和事务回滚；
- 两个客户端同时基于同一修订写入，仅一个成功；
- 批量参数第 100 条失败时前 99 条也不落库；
- 作业与业务修订同事务登记，不出现已提交修订无作业；
- 多 Worker 使用 `SKIP LOCKED` 不重复领取；
- Worker 崩溃、心跳过期、重试和完成时当前修订已变化的 `STALE` 处理；
- 发布并发只有一个 `PUBLISHED` 事件和一个当前发布指针；
- 审计表业务账号无 UPDATE/DELETE 权限；
- 角色移除并发时仍至少保留一名权限管理员和一名部门预算负责人。

### 2.6 端到端验收

端到端测试通过 API 建立输入和状态，再以浏览器验证关键页面的展示与按钮门槛。浏览器测试不重复计算预期金额，预期值来自独立测试构造器和黄金样例。

关键旅程：

1. 创建草稿、冻结快照、确认组合；
2. 锁定入口总值、生成建议、维护并整套确认校区入口；
3. 形成入口明细、比例边界和计划新生；
4. 保存并确认资源财务参数，保存折扣参数并由部门预算负责人独立确认；
5. 完整计算、定位阻断、生成和应用候选；
6. 正式方案确认、再次完整复算、发布；
7. 从发布基线派生新草稿，证明原版本只读；
8. 导出参数、结果、校验和审计包并校验哈希。

  spec_anchor: docs/product/phase-1-acceptance-cases.md#...

  automated_tests:
    - tests/golden/test_cross_fiscal_year_carryover.py::test_ab_049e

CI 从验收文档解析 `### AB-*` 标题；当前阶段强制：

- 文档标题数必须为 96；
- AB-050 至 AB-061 在追踪清单按序且各出现一次；
- 不允许追踪不存在的 ID；
- 每项至少绑定一个自动化测试；确实只能人工验证的 UI 可用性项也必须绑定底层自动化规则测试和人工证据模板；

## 4. 求解器专项测试

### 4.1 小规模穷举对照

对不超过 6 个入口变量、4 个比例水位和 4 个折扣变量的小模型枚举全部离散解，与 CP-SAT 输出比较：

- 可行集合一致；
- `INFEASIBLE` 与穷举无解一致；
- 每层字典序最优指标一致；
- 稳定 ID 最终决胜一致；
- 三个 profile 收敛时去重标签一致。

这是证明模型编码未偏离计算内核的核心测试。阶段 4 先运行 24 个可审阅的确定性小模型（2 至 5 个入口变量，含可行与不可行样本）；阶段 5 扩展为至少 10,000 个随机小模型，并保存所有反例。

### 4.2 复算与状态

- 每个 `OPTIMAL` 解交给纯内核复算，结果哈希必须一致；
- `ENTRY_ONLY` 内核复算失败后只禁用该精确入口向量；小模型须与完整穷举的首个可行字典序最优解一致；
- 候选复算上限耗尽必须返回 `INCOMPLETE`，只有禁配后完整入口空间被证明耗尽才能返回 `INFEASIBLE`；
- `ENTRY_AND_RATES` 必须验证同组等百分点推进、逐行触界退出、锁定行不变和两个比例类型的独立水位；
- 组级状态表必须与正式内核的四季最大余数人数、班均、`R00/R10/R01/R11` 收入逐项一致；跨组 CP-SAT 结果再由全量内核复算；
- 三个贡献 profile 与小模型穷举最优解逐一一致；状态表超限必须返回 `INCOMPLETE`，模型与复算漂移必须返回 `FAILED`；
- 只返回 `FEASIBLE`、`UNKNOWN` 或触发硬超时均断言为 `INCOMPLETE`；
- 只有完整硬约束模型的 `INFEASIBLE` 可以解锁下一阶段；
- 修改任一输入后旧证明、候选和折扣解锁全部失效；
- 折扣解锁必须经过数据维护人员申请和部门预算负责人独立确认，并精确绑定当前修订、输入指纹、运行与第二阶段不可行证明；优化运行固化所用确认 ID；
- 第三阶段必须验证折扣 1,000 ppm 步长、锁定和确认边界，并同时覆盖收入缺口向上、收入超额向下、仅综合折扣未闭合时双向可调和锁定值导致精确不可行；
- 折扣阶段的整数微元乘除、六位小数四舍五入、含税转换、当季确认、跨季和期初结转必须与正式内核逐项一致；
- 64 位范围无法证明时必须停止，不允许截断或缩小业务域。

### 4.3 确定性

同一模型在同一支持平台连续运行 100 次，断言模型哈希、求解状态、决策向量、候选顺序和结果哈希完全一致。依赖升级前后运行固定回归集；输出变化必须升级 `optimization_model_version` 并形成差异报告。

## 5. 性能与容量测试

基线数据规模：5,000 个预算组合、20,000 条季节结果、500 个修订、50 个并发在线用户。使用脱敏或合成数据，不复制学员明细。

| 场景 | 目标 |
|---|---|
| 普通分页和汇总查询 | P95 < 2 秒，错误率 < 1% |
| 完整年度计算 | P95 < 60 秒 |
| 5,000 行批量参数预校验 | < 10 秒，事务提交 < 5 秒 |
| 修订差异摘要 | P95 < 5 秒 |
| 调平作业 | 记录阶段分布；5 分钟软超时、15 分钟硬终止语义正确 |
| 50 用户读、10 用户并发写 | 无丢失更新、死锁可控、冲突有明确响应 |
| 两 Worker 领取 1,000 作业 | 无重复执行业务结果，队列最终清空 |

压测报告必须同时给出数据库 CPU/IO、慢查询、队列等待、内核与求解阶段耗时、结果批量写入耗时。未达标优先优化索引、预聚合、批量写入和模型；不得删校验或扩大容差。

## 6. 安全与权限测试

- 未登录、过期会话、伪造部门范围和 CSRF 请求被拒绝；
- 三个角色逐命令正反向授权；多角色用户仍必须执行独立动作；
- 普通用户不能访问其他部门预算、导出或作业详情；
- 角色移除后新请求立即按新权限处理，历史角色快照不变；
- 文件上传和导出覆盖路径、MIME、公式注入、超大文件和恶意文件名；
- 日志、错误、作业载荷和审计抽样扫描不得出现 Cookie、令牌、原始学员行或私有连接信息；
- 依赖和镜像执行漏洞、许可证和软件物料清单扫描；高危漏洞未豁免不得发布。

## 7. 数据迁移与影子核验

首批上线按以下顺序：

1. 导入并校验赛道、产品、年级、科目、校区、季节和续班关系主数据；
2. 保存原 Excel 文件哈希、导入批次和只读附件，不导入公式字符串作为执行逻辑；
3. 创建对齐的来源快照，聚合历史入口、组合和比例分子分母；
4. 导入 FY27 学校版目标、入口总值、组合、参数初值和人工依据；
5. 生成第一个不可变系统修订并完整计算；
6. 按部门、赛道、季节和代表性明细与 Excel 做差异核验；
7. 每个差异标记为规则修正、Excel 兼容引擎问题、参数不同或数据批次不同，禁止无原因调数；
8. 部门预算负责人确认影子核验报告后才开放系统正式方案确认和发布。

迁移脚本必须可重复执行到临时 schema，并产生行数、主键、合计、哈希和错误清单。生产迁移只允许向前追加；回滚应用版本时保留已创建修订、审计和来源证据，不运行破坏性数据回滚。

## 8. 分阶段实施

### 阶段 0：工程基座

交付：代码仓库、依赖锁、CI、PostgreSQL 迁移框架、API/Worker 骨架、认证适配器、结构化日志。退出条件：空系统可部署、迁移可向前/回退结构、健康检查和最小安全扫描通过。

### 阶段 1：版本、来源和治理输入

交付：不可变修订、组件版本、来源快照、组合、入口总值、校区入口、参数版本、确认和失效图。退出条件：AB-001 至 AB-036 对应测试通过，关键并发和幂等测试通过。

### 阶段 2：确定性计算内核

交付：入口明细、四季人数、最大余数、班均、收入、综合折扣、结转和发布校验。退出条件：AB-037 至 AB-049E、性质测试和 FY27 黄金子集通过；相同输入 100 次哈希一致。

已落地子集：`phase1-headcount-v1` 覆盖 AB-037 至 AB-039P 的四季人数分支、定量新生优先、分组最大余数、同余数稳定键决胜、缺失输入阻断和 100 次相同输入确定性；`phase1-class-size-v1` 覆盖 AB-040 至 AB-044，并已实现 AB-048A 至 AB-048C 的完整资源财务参数版本、独立确认和依赖失效；`phase1-revenue-v1` 覆盖 AB-045 至 AB-047 和 AB-049 至 AB-049E，包括加权综合折扣、零分母 N/A、折扣步长/容差、预算含税转换、实际不含税类型隔离、期初结转、跨季链和年度汇总。折扣参数版本必须由部门预算负责人独立确认，未确认返回稳定 409 阻断，确认指纹随收入结果入库。`phase1-target-closure-v1` 已落地学校版部门与赛道目标整套锁定、收入计算前门禁、正负一万元精确边界、逐赛道禁止抵消、缺口/超额状态和依赖失效，覆盖 AB-004 与 AB-005 的确定性内核及数据库纵向旅程。

### 阶段 3：年度预算工作流与页面

交付：P01 至 P09、P11、P12 的查询和命令流程，正式确认、发布、差异、审计和导出。退出条件：不含调平的可闭合基线能够端到端发布，权限和故障恢复测试通过。

### 阶段 4：调平引擎

交付：入口、比例、折扣三阶段模型，三个贡献 profile、不可行/未完成区分、折扣解锁、P10 和候选应用。退出条件：AB-050 至 AB-061、小规模穷举对照、确定性和硬超时测试通过。

已落地求解内核：`phase1-deterministic-rebalancing-v3` 已实现固定入口总值内的入口结构调整、续班率与新生占比并列等百分点调节，以及双人确认解锁后的明细折扣调节。第二阶段通过局部精确状态表组合四季人数，第三阶段用整数微元乘除约束直接闭合收入、结转和综合折扣。两阶段的最优解都必须交由正式内核复算；精确不可行、未完成和技术失败保持不同状态。

显式撤销产生新的不可变修订，恢复应用前输入并重新登记完整复算，不删除或改写历史。应用修订及其四类纯计算后续修订允许撤销；链上输入修改、非计算修订、正式确认或发布均阻断。撤销与草稿写入共用预算锁，取消旧的排队中／运行中／未完成计算作业；Worker 不得把已取消作业改回成功或未完成。覆盖复算完成后撤销、排队及运行中撤销、并发重复点击、幂等重放、跨部门和角色拒绝、人工保存保护以及数据库不可变触发器。

求解在独立子进程执行，父进程拥有包含启动、建模和各阶段求解在内的总墙钟期限，超时强制终止并回收子进程。真实 CPU 死循环验证父事件循环仍可响应；API 将超时记为 `INCOMPLETE/HARD_TIME_LIMIT`，不留下候选或解锁证明。硬终止无法获取子进程最终阶段，返回初始阶段占位但不声称任何阶段已穷尽。进程故障记为 `FAILED/SOLVER_PROCESS_FAILED`。

P12 版本与审计三个纵切已落地：`GET /revisions/{id}/diff` 在同一年度预算内比较任意两个不可变修订，返回版本关系、状态快照和组件清单差异；`GET /audit-events` 以年度预算为强制范围，支持修订、事件、对象、操作者、角色、原因和时间窗口筛选，并使用稳定游标分页。`GET /revisions/{id}/detail-diff` 进一步以稳定业务键比较比例、计划新生、资源财务和折扣明细，同时展示系统值、人工值、最终值、确认状态、原因、来源与候选过程；业务变化计数只比较业务值、确认和状态，批次原因或行哈希变化不冒充业务变化。`POST /revisions/{id}:export` 登记异步审计归档作业，Worker 按申请时的审计截止时间生成不可变 ZIP；包内含范围清单、来源、组件参数、结果与校验、预算链审计及逐文件 SHA-256，元数据与下载接口均按部门隐藏。页面采用版本脊柱、组件变更账本、逐行证据页、审计时间轴和归档签出条组织证据。数据库集成回归覆盖跨部门隐藏、原因筛选、审计游标无重复翻页、单条业务变化识别、归档幂等、Worker 生成、ZIP 内容和校验和、下载鉴权及归档表不可变触发器。

### 阶段 5：影子运行与上线

交付：全量迁移、FY27 差异报告、性能和安全报告、96 项追踪清单、运维手册、备份恢复演练。退出条件：全部 96 项 `passing`，无未处置 P0/P1 缺陷，部门预算负责人完成业务验收。

每个阶段只向前交付可验证能力；第二期自然滚动预测和第三期滚动补缺不得作为一期“顺手预留”进入表、接口或页面。

## 9. 发布与回退

应用发布采用向后兼容的数据库迁移：先扩展 schema，再发布可双读/双写的应用，回填并验证，最后在后续版本移除旧字段。数据库备份恢复演练至少在上线前完成一次，并记录恢复点和恢复耗时。

若新应用异常，可以回退应用镜像并暂停新写命令；已经提交的预算修订、确认、发布和审计绝不删除。求解器或计算规则回退必须保留原 `engine_rule_version`，新运行使用新版本号，不能在同一版本号下生成不同结果。

## 10. 完成定义

一期详细实现只有同时满足以下条件才可宣布完成：

- 技术文档、ADR、OpenAPI、迁移和代码一致；
- 96 项验收全部有自动化证据且通过；
- 单元、性质、黄金、集成、求解、性能和安全门槛通过；
- FY27 影子核验差异全部有结论；
- 发布、备份恢复、Worker 崩溃恢复和审计导出完成演练；
- 运维人员能从告警定位到修订、作业、稳定错误码和修复入口；
- 已发布基线可被第二期以稳定 ID、完整参数、结果、锁定和审计快照读取；
- 不存在强制发布、隐藏精度、静默补人、跨赛道抵消或自动扩大容差路径。
