## 本步完成

`packages/headcount/opening.py` 提供独立纯函数 `prepare_bi_opening`：

- 只接受 FY28 及以后、上一财年春季来源；记录快照日期、来源批次、快照标识、续班率版本与规则版本。

- 用精确分数保留招生人次乘续班率的理论值，不提前逐行四舍五入。

- 141 项单元测试通过；新增文件 Ruff 与严格类型检查通过。

## 上一步边界（已由下述入库步骤推进）

本函数尚未接入人数内核、数据库或 API；来源快照标识和参数版本目前只是输入值，尚未通过数据库验证其冻结状态、权限和关联。既有人数内核 v1 第一季仍按原规则计算，不能宣称其已支持新的期初老生规则。

下一步须实现不可变期初老生版本与 API，绑定完整组合版本、冻结来源与参数版本，校验目标覆盖；明确区分显式零和缺失。随后将其纳入输入指纹、下游失效、人数取整、自动调平和发布门禁。FY27 的固定整数输入应走独立历史承接路径，不调用本 BI 准备函数。完成整条链路与集成测试前，不用于正式发布。

## 本步：不可变准备版本与 API

- 新增迁移 `20260907_0026` 和 `opening_student_version`，外键关联修订、来源组件、组合及比例版本；数据库触发器禁止修改、删除。
- `POST /api/v1/revisions/{revision_id}/opening-students`：数据维护人员权限，必带 `If-Match` 和 `Idempotency-Key`；创建追加修订、审计与幂等回执。
- `GET /api/v1/opening-student-versions/{version_id}`：通过所属修订验证部门访问权限。
- 来源必须属于当前预算的同部门冻结快照；日期、批次、分区、组件哈希从数据库读取，不接受客户端覆盖。
- 组合和比例版本必须属于同一年度预算。续班率读取服务端参数，匹配暑假、来源年级、赛道、产品、校区；历史比例观测季不与招生来源春季混淆。
- 所有启用组合必须由升年级后的来源或 `zero_combination_ids` 显式覆盖；遗漏、重复、未知组合或零值与来源重叠均阻断。请求原因保留在不可变内容与审计中。
- 保存移除旧人数、班均、收入、目标闭合、优化运行、折扣解锁和正式确认。新组件进入修订清单及其哈希。
- 本接口仍接收维护人员提交的汇总，**尚未与冻结提取内容核验**。返回 `source_verification=DECLARED_ROWS_NOT_EXTRACT_VERIFIED` 和 `status=PREPARED_NOT_CALCULATION_READY`，不能声称已自动从 BI 取数。
- 新组件存在时，人数/优化共用的输入加载器返回 `OPENING_CALCULATION_NOT_READY`；正式发布检查 `OPENING_CALCULATION_READY` 不通过。不会静默使用第一季老生为零的旧内核。

验证：154 项单元测试通过；全库 Ruff、格式和严格类型检查通过。迁移在本机 `budget_acceptance_20260905_real` 隔离库成功执行，新增 1 项真实 PostgreSQL 不可变性测试通过（测试记录事务回滚）。服务测试覆盖保存、重放、权限、来源状态/部门、比例匹配、覆盖与计算阻断，但尚不是完整真实数据库 API 端到端测试。测试后已停止本轮启动的 PostgreSQL，保留卷。

下一步：补齐冻结提取内容与汇总输入的核验及真实 API 端到端用例，再将期初老生接入人数内核、优化模型与完整发布链。接入时必须处理组合/比例版本变化导致的失效，不能直接撤掉本步阻断。FY27 不抽取、不重建、不回写。

## 本步续接：冻结招生来源核验

代码检查确认：旧快照仅保存续班率与新生占比参考，没有普通口径招生人次，不能拿三分之二出勤字段替用。

- FY28 起的抽取请求新增 `招生人次` 和 `目标标识(目标,数据)`；FY27 抽取字段及已有快照保持原状。本轮没有执行线上抽取。
- 快照构建对上一财年春季单独生成 `OPENING_ACTUAL_ENROLLMENT_V1`：仅使用标记为“数据”的记录，按完整来源维度汇总普通招生人次，排除“目标”记录。实际标记缺失、招生字段缺失/空白/负数/非整数均阻断；显式 0 保留。该字段不参与新生占比分母计算。
- 利用既有不可变 `source_metric_aggregate` 存储汇总，纳入快照聚合哈希，不增新表。比例参考生成明确只读取两个比例指标，避免把新增招生汇总误当比例。
- 期初版本保存时查询同一冻结快照、同一来源数据集、同一春季的招生汇总，逐键、逐值核对全部提交来源；不允许通过遗漏来源后填显式零绕过。旧快照无该指标返回 `OPENING_FROZEN_ENROLLMENT_MISSING`，不原地回填冻结历史。
- 新保存版本标记 `FROZEN_AGGREGATES_MATCHED`，保留核对的聚合哈希；旧版本原内容不变。该标记只证明与冻结汇总一致，并非本轮进行了 BI 在线复核。
- `PREPARED_NOT_CALCULATION_READY` 及计算、发布阻断继续保留。人数内核接入与真实 API 全链路测试仍待完成，不能宣称本步已具备正式计算能力。

## 本步续接：人数内核与真实 API

- 新增 `phase1-headcount-opening-v2`。FY28 起纯人数内核必须收到完整期初老生映射，不能隐式使用零；FY27 保留 v1，不承接该新映射。
- 暑假老生使用精确跨年续班理论值，老生、新生分别沿用既有分组最大余数取整；非入口新生从未取整老生与新生占比反推。后续季度使用上一季整数总人次，保持原预算行。
- 人数服务按当前修订加载期初版本，核验同一年度预算、来源组件、组合版本、比例版本、核验标记、内容哈希及明细覆盖。依赖版本变化返回 `OPENING_BASIS_STALE`，旧声明未核验版本不可使用。
- API 人数请求须显式指定 `calculation_rule_version=phase1-headcount-opening-v2`；规则不匹配返回 `HEADCOUNT_RULE_VERSION_MISMATCH`，不静默换算法。人数结果保存 v2 规则并将期初内容哈希纳入输入指纹；v1 指纹结构保持不变。
- 历史期初版本内的 `PREPARED_NOT_CALCULATION_READY` 是创建时状态，不回写不可变记录；现在是否可计算由服务核验、显式规则和计算校验共同判断。

验证：177 项单元测试通过，Ruff、格式和严格类型检查通过。新增真实 PostgreSQL API 测试通过：合成 FY28 来源冻结、比例及组合生成、期初保存/幂等重放/读取、暑假 100×80%=80 老生与20新生、秋季整数承接、跨部门隐藏资源、比例版本重建后过期阻断。该 API 样例未补齐全部后续季度比例，不是全年可发布黄金样例；完整四季数学推演由单元测试覆盖。
