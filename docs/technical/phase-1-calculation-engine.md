# 第一期计算与调平引擎

## 1. 设计目标

计算内核把一个不可变预算修订转换为可复算的四季人数、班均、收入、结转、目标差异和发布校验；调平引擎只在同一输入快照上生成候选参数差异。二者共用公式、取整和校验实现，求解器不得维护第二套“近似业务公式”。

每次运行必须显式绑定：

- `budget_revision_id`；
- 修订引用的全部组件版本和来源快照；
- `engine_rule_version`；
- 维度映射版本；
- 调平时的 `optimization_model_version`。

相同输入、规则版本和作业类型必须得到相同结果哈希。页面临时值、数据库行顺序、中文名称和系统当前时间都不得进入计算。

## 2. 内核边界

推荐公开接口：

```python
calculate(input: CalculationInput) -> CalculationOutput
validate_for_publish(output: CalculationOutput, confirmations: ConfirmationSet) -> PublishCheck
optimize(input: OptimizationInput, profile: ScenarioProfile) -> OptimizationOutput
recalculate_candidate(input: CalculationInput, changes: ChangeSet) -> CalculationOutput
```

`calculation_kernel` 是无数据库、无网络、无 OR-Tools 依赖的纯函数包；`optimization_adapter` 可以依赖求解库，但任何候选必须再调用 `recalculate_candidate`。内核不读取“当前版本”指针，只接收已经组装并完成规范排序的输入对象。

## 3. 数值与排序规则

### 3.1 正式单位

- 业务输入人数和最终人数：非负整数；
- 比例参数：整数 ppm，`100% = 1,000,000 ppm`；
- 续班率和反推型新生占比调平步长：`100 ppm`，即 0.01 个百分点；
- 明细折扣调平步长：`1,000 ppm`，即 0.1 个百分点；
- 金额：十进制元，不使用 IEEE 754 二进制浮点；
- UI 格式化值只供展示，不能反向进入内核。

理论人数使用精确有理数计算。`season_budget_result` 中的 `numeric(20,9)` 只是解释性序列化值，采用 `ROUND_HALF_UP` 保留九位小数；最大余数排序和组总量取整始终使用序列化前的精确分数。

金额计算在十进制精度 38 下执行，每条正式金额结果采用 `ROUND_HALF_UP` 量化到 `0.000001` 元后保存。汇总只对已经量化的明细正式金额求和；目标比较使用该六位小数正式值，不使用页面显示的万元或百分比舍入值。

### 3.2 稳定顺序

所有输入集合先按稳定内部 ID 升序规范化。最大余数相同、优化目标完全相同或批量错误并列时都使用稳定 ID，不使用名称、创建时间或数据库自然顺序。

### 3.3 非负数四舍五入

人数理论合计只允许非负值，组总量使用：

`rounded_total = floor(exact_total + 1/2)`

这明确排除语言运行时可能采用的银行家舍入。

## 4. 计算输入装配与前置校验

Worker 在一个可重复读事务中按预算修订清单装配输入，完成以下检查后计算输入指纹：

1. 所有组件版本存在，内容哈希与清单一致；
2. 学校版部门与全部赛道目标已经整套锁定，金额、层级和来源证据完整；
3. 启用组合六个维度完整，公共五维不存在仅入口属性不同的重复行；
4. 财年入口总值是已锁定非负整数，整套校区入口已经确认且合计严格相等；
5. 参数键能精确匹配组合和季节，不做模糊或通配回退；
6. 比例值、边界、锁定和精度合法；
7. 资源财务参数完整，转换系数大于 0，确认比例在 0% 至 100%；
8. 来源快照已 `FROZEN`，花名册与唯一最新宽表分区对账通过；
9. 季节顺序和续班关系形成无环图，每个来源组合最多有一个下一季去向；去向只能改变年级，赛道、产品、科目、校区保持不变。

缺失业务输入、待确认或业务边界错误生成稳定 `ValidationResult`，运行可以以 `SUCCEEDED` 保存已能计算的结果，但 `publishable=false`；不得用默认零或近似参数补齐。数据损坏、哈希不一致、公式异常属于技术失败，运行状态为 `FAILED`。

## 5. 入口建议和入口初始值

### 5.1 校区建议

设锁定财年入口总值为 `E`，无历史校区人工整数预留合计为 `R`：

1. 若 `R > E`，生成 `ENTRY_RESERVATION_EXCEEDS_TOTAL`；
2. 有历史校区 `c` 的理论建议为 `(E-R) × H_c / SUM(H)`；
3. 对有历史校区执行最大余数法，整数合计必须为 `E-R`；
4. 全部校区无历史时，不运行比例公式，要求全部人工整数建议严格合计到 `E`。

建议只生成解释结果，不成为入口下拆输入；入口下拆只读取已经整套确认的校区入口确定值。

### 5.2 校区内入口明细

每个校区独立执行两段分配：

1. 新产品人工比例先计算理论预留，比例合计不得超过 100%；新产品预留总量按理论预留合计四舍五入，再在新产品内用最大余数法分配；
2. 校区确定值减去新产品整数预留后，按存量入口组合历史业务新生人次占比计算理论值，并用最大余数法分配全部剩余额度。

同一段内余数相同按组合稳定 ID。历史分母为 0 且仍有剩余额度时不得跨产品或校区借用比例，必须转为完整人工计划。两段整数结果之和必须严格等于校区入口确定值。

分配得到的整数是 `entry_initial_value`。默认软边界为初始值的 80% 至 120%，转换为候选整数范围时下限向上取整、上限向下取整；资源硬边界始终优先。初始值为 0 时不生成比例软边界，只有业务方填写计划值、硬上下限和原因后才进入入口调平变量集。

## 6. 四季人数推演

季节使用版本化 `fiscal_season_index` 从 1 至 4 顺序计算，不依赖中文季节名称。

### 6.1 第一季

> 2026-09-07 用户确认更新（待实现）：第一季老生必须由上一财年春季同赛道、产品、科目、校区招生人次经过跨年续班得到；七升八、八升九，九年级不续班，八年级地理/生物不续入九年级。来源可选学员花名册或指标汇总宽表，字段口径及来源适配仍待核实，快照日期和来源批次必须留存。此更新仅适用于跨财年春→暑，不改变财年内的同预算单元续班规则。当前内核尚未实现此输入，不能据此宣称已经支持。

- FY28 起已使用版本化期初来源及升年级映射，规则为 `phase1-headcount-opening-v2`；人数、Worker、精确枚举、CP-SAT、候选应用/撤销与发布指纹均承接该输入。FY27 保留已定版历史路径，不访问 BI 重建；完整说明见 `opening-students-progress.md` 的最终收口章节；
- 入口组合的新生使用入口明细整数分配，是定量新生；
- 非入口组合没有其他新生绝对量时进入计划新生人次分支，空值或未锁定产生阻断校验；
- 已锁定计划新生 0 是有效输入，不等于空值。

### 6.2 后续季节老生

对续班关系边 `source -> target`：

`target_old_theory += source_previous_integer_total × retention_rate_ppm / 1,000,000`

来源使用上一季取整后的总人次。老生保留来源赛道、产品、科目和校区，只按续班关系改变年级。若多个合法来源汇入同一目标，先累加精确理论值再取整；缺失目标组合或出现一对多去向均为阻断。

### 6.3 当季新生来源分支

每条明细必须且只能命中一个来源：

1. `ENTRY_ALLOCATION`：第一季入口整数；
2. `LOCKED_MANUAL_PLAN`：老生理论为 0 时的已锁定计划新生整数；
3. `RATE_INFERRED`：老生理论大于 0 时，按反推型新生占比计算。

反推公式使用精确分数：

`new_theory = old_theory × share_ppm / (1,000,000 - share_ppm)`

`RATE_INFERRED` 的 `share_ppm` 最大为 `999,900`。定量新生行的占比仅在取整后计算结果，不读取或生成可调参数。

### 6.4 分组最大余数法

取整组为“赛道＋校区＋季节”，老生和新生分别执行：

```text
group_target = floor(sum(all exact theory) + 1/2)
fixed_total = sum(quantitative integer inputs)
adjustable_target = group_target - fixed_total
base_i = floor(adjustable_theory_i)
tail = adjustable_target - sum(base_i)
按 exact remainder 降序、stable_id 升序给前 tail 行各加 1
```

老生没有定量保留项；新生的入口分配和锁定人工计划属于 `fixed_total`。若 `adjustable_target < 0`、`tail` 超出可调行数或最终合计不等于 `group_target`，视为内核不变量破坏并技术失败，不得静默改数。

`rounding_trace` 保存理论分数的规范字符串、整数部分、精确余数排序、尾差归属和稳定 ID。完成后重算：

- 实际续班率：整数老生 / 上一季来源整数总人次，分母为 0 时不适用；
- 实际新生占比：整数新生 / 整数总人次，总人次为 0 时不适用。

当前已实现的 `phase1-headcount-v1` 内核使用 Python `Fraction` 保存精确理论数，不以数据库九位小数参与余数排序。任一取整组缺少计划新生或比例输入时，该类人数不生成整数结果；系统保存已经能够确定的理论值和稳定阻断校验，并将结果版本标记为不可发布，不使用 0 补齐后继续传导。现有续班关系代码为 `SAME_BUDGET_ROW`，因此当前纵切保持同一组合稳定 ID；未来只有在版本化续班关系主数据落地后，才允许改变年级映射。

## 7. 班均、收入和结转

### 7.1 班均

完整季节预算明细的 `integer_total = integer_old + integer_new`：

- `0`：`NO_PLANNED_CLASS`；
- `1..minimum_class_size-1`：`BELOW_MINIMUM_CLASS_SIZE`；
- 大于等于班均：`PASS`。

同一启用组合四季总人次均为 0 时另生成 `ENABLED_COMBINATION_ALL_SEASONS_ZERO`。班均不得跨科目、校区或其他维度合并。

### 7.2 明细收入

对每条季节明细依次计算：

```text
discounted_tuition = list_price × detail_discount_rate
business_quarter_revenue = integer_total × discounted_tuition
net_of_tax_base = business_quarter_revenue / budget_tax_conversion_factor
current_recognized = net_of_tax_base × current_recognition_rate
cross_season = net_of_tax_base × (1 - current_recognition_rate)
```

`cross_season_recognition_rate` 只能派生，不能作为独立输入。年度预算路径才使用含税转换系数；以后滚动预测读取不含税实际字段时必须调用不同的 `ActualNetRevenue` 输入类型，类型层禁止再次转换。

### 7.3 财季链和跨财年边界

- 第一季 `quarter_recognized = current_recognized + opening_carryover_revenue`；
- 第 2 至 4 季 `quarter_recognized = current_recognized + previous_season.cross_season`；
- 年度总结转为四季 `quarter_recognized` 之和；
- 第 4 季 `cross_season` 只写入 `next_fiscal_year_opening_carryover_yuan`，不额外计入本财年年度总结转。

期初结转按正式财务适用键分配到明细；键无法精确匹配或同一键重复时阻止发布。季度、赛道和部门汇总都由明细正式金额相加得到。

### 7.4 综合折扣

对部门、赛道的年度和季节层级分别计算：

`composite_discount = SUM(integer_total × list_price × detail_discount) / SUM(integer_total × list_price)`

分母为 0 时为不适用；存在必须达成的目标但结果不适用时发布失败。目标差异使用精确 ppm 比较，绝对值 `<= 500 ppm` 才通过。

## 8. 目标与发布校验

目标差异统一为 `calculated_revenue - target_revenue`。智慧伴学、智慧空间和部门合计分别要求绝对值 `<= 10,000.000000` 元，恰好等于边界通过，不能跨赛道抵消。

每条校验返回稳定编码、范围键、严重级别、实际值、规则、依赖指纹和修复入口。发布检查至少覆盖：快照与对账、组合、入口、比例与锁定、计划新生、资源财务参数确认、人数不变量、班均、收入目标、综合折扣、确认、权限和审计完整性。

正式方案确认后，系统必须对同一修订重新完整计算；发布事务再次比较 `input_fingerprint`、`result_hash` 和确认指纹。任一不一致都返回 `PUBLISH_INPUT_CHANGED`。

## 9. 调平模型

### 9.1 方向和阶段

目标缺口和超额使用同一模型，方向由各赛道目标差异决定。入口总值固定，赛道目标分别闭合。变量按阶段逐级开放：

1. `ENTRY_ONLY`：只允许校区及入口明细整数重新分配；
2. `ENTRY_AND_RATES`：只有第一阶段在完整模型上被精确证明不可行后，才同时开放入口、续班率和新生占比；
3. `ENTRY_RATES_AND_DISCOUNT`：只有第二阶段精确不可行、数据维护人员发起并由部门预算负责人确认当前修订的折扣解锁后，才开放明细折扣。

后一阶段保留前面阶段变量，避免把某个“最接近但不闭合”的前阶段结果错误固定后造成假不可行。计划新生、班均、原价、含税转换系数、结转节奏、入口总值和锁定比例永远不是变量。

### 9.2 入口变量

- 所有入口变量为整数，财年合计严格等于锁定入口总值；
- 逐校区和明细满足业务硬上下限；
- 默认 80% 至 120% 是软边界，优先减少越界人数，但不得压过收入、班均等硬约束；
- 初始值为 0 且未维护计划和硬边界的组合不建变量；
- 每个候选完整展示校区和明细的前后值及收入边际影响。

### 9.3 比例水位变量

每个赛道、每类比例和调平方向建立一个离散水位变量，单位为 100 ppm。每个可调参数的建议值是：

```text
up:   min(current + water_level, confirmed_upper_bound)
down: max(current - water_level, confirmed_lower_bound)
```

未确认边界、被锁定、非 100 ppm 整数倍或属于定量新生结果的参数不进入变量集。某参数触界后由截断函数自然退出，其他参数继续等百分点推进；不得按当前比例、可调空间或收入边际加权水位。

### 9.4 三类比例贡献软目标

比例阶段分别求解平衡 50/50、留存侧 70/30、招生侧 30/70 三个 profile。贡献采用 [ADR-0147](../adr/0147-attribute-parallel-rate-contributions-symmetrically.md) 的对称归因。

设入口调整后的共同基准收入为 `R00`，只调整续班率为 `R10`，只调整新生占比为 `R01`，两者同时调整为 `R11`：

```text
retention_contribution = ((R10 - R00) + (R11 - R01)) / 2
new_share_contribution = ((R01 - R00) + (R11 - R10)) / 2
```

两项之和必须等于 `R11 - R00`。按赛道计算后再汇总到部门；贡献 profile 是软目标，不设置额外业务容差。

### 9.5 折扣变量

明细折扣建议必须保持在合法边界且为 1,000 ppm 的离散步长。部门、赛道的年度和季节综合折扣目标全部是硬约束，完整精度差异不得超过 500 ppm。折扣解锁只对绑定的预算修订和输入指纹有效，上游变化后不进入模型。

### 9.6 字典序目标

任何层级都先满足全部硬约束，再按独立优化轮次锁定前一目标的最优值，禁止用一个巨大权重常量模拟字典序：

1. 对比例方案最小化与目标贡献份额的绝对偏离；
2. 最小化单条比例参数最大调整 ppm；
3. 最小化比例参数总调整 ppm；
4. 最小化入口软边界越界总人数；
5. 最小化单条入口最大调整人数，再最小化入口总调整人数；
6. 折扣阶段再最小化单条折扣最大调整和折扣总调整；
7. 仍相同则求稳定 ID 顺序下完整决策向量的字典序最小值。

入口单独阶段从第 4 项开始。每轮的最优值作为下一轮等式约束保存，求解记录保留全部目标值。

## 10. 精确求解、复算和状态

参考实现使用 CP-SAT 的整数变量、乘积/商余约束和离散允许表，编码与计算内核相同的 ppm、组取整、班均、收入和目标约束。模型构建前执行 64 位范围证明；不能证明安全时不截断数值，直接返回 `CALCULATION_INCOMPLETE: MODEL_RANGE_UNPROVEN`。

正式求解固定随机种子、单工作线程、稳定变量顺序和模型版本。状态映射：

| 求解结果 | 系统语义 |
|---|---|
| 每一轮均 `OPTIMAL`，且内核复算哈希一致 | 保存可行候选 |
| 完整硬约束模型返回 `INFEASIBLE` | 保存业务不可行结论和证明摘要 |
| 仅得到 `FEASIBLE` 但未证明字典序最优 | 计算未完成，不进入正式候选列表 |
| `UNKNOWN`、超时、资源不足、范围无法证明 | 计算未完成，可按相同输入重试 |
| `MODEL_INVALID` 或内核复算不一致 | 技术失败并告警 |

默认 5 分钟软超时只产生进度，15 分钟硬终止后若未达到 `OPTIMAL` 或 `INFEASIBLE` 即为计算未完成。系统不得把“未找到”写成“不可行”。

当前保留两个可替换适配器：`ExactEnumerationAdapter` 用于有界小模型和穷举对照；`DeterministicCpSatAdapter` 使用 OR-Tools 9.15 承载生产整数模型，固定随机种子、单工作线程，为每个字典序目标单独求解并回写最优值约束，最后按稳定 ID 消除多解。CP-SAT 适配器在建模前对变量、线性表达式和约束边界执行 64 位范围证明；范围无法证明时返回 `INCOMPLETE: MODEL_RANGE_UNPROVEN`，不截断数值。

`ENTRY_ONLY` 已有首个业务编译器：入口整数变量、固定入口总值、不可调明细、人工硬边界、80%–120% 软边界、最大/总调整和稳定 ID 决胜均进入 CP-SAT。人数、班均、收入和目标闭合仍以正式计算内核为权威；CP-SAT 每次给出的结构最优解必须完整复算，未通过时只排除该精确入口向量并继续求解。只有全部剩余入口向量均被求解器证明耗尽，才返回 `INFEASIBLE: CP_SAT_LAZY_VALIDATION_SPACE_EXHAUSTED`；达到时间或候选复算上限返回 `INCOMPLETE`。该路径通过 `solver_adapter=CP_SAT_ENTRY_ONLY` 显式启用。

`ENTRY_AND_RATES` 业务编译器进一步为每个“赛道＋比例类型”建立独立整数水位，按 100 ppm 等百分点推进；同组明细共享水位，先触及确认边界的明细固定在边界，其他明细继续推进。锁定、边界未确认和定量新生行固定为原值。该路径通过不改变最大余数口径，按正式取整单元“赛道＋校区”编译局部精确状态表：表内直接使用正式人数、班均和收入内核计算四季人数，以及 `R00`、`R10`、`R01`、`R11` 六位小数收入。CP-SAT 在全局层面组合各局部表，直接约束部门/赛道收入目标、年度/季度综合折扣，并把三个 profile 的对称贡献偏离作为第一层整数目标。

组状态表完整生成且 CP-SAT 返回 `INFEASIBLE`，才构成第二阶段的精确不可行证明；任一组超过独立配置项 `maximum_group_table_rows` 时返回 `INCOMPLETE: CP_SAT_GROUP_TABLE_LIMIT_EXCEEDED`。该上限只约束局部组状态表构建，不复用 `maximum_candidate_validations`。求解器得到的 `OPTIMAL` 决策仍须交给全量正式内核复算；若目标、校验码或结果不一致，返回 `FAILED: CP_SAT_BUSINESS_MODEL_RECOMPUTATION_MISMATCH`，不得排除该结果后继续伪造可行空间。该路径通过 `solver_adapter=CP_SAT_ENTRY_AND_RATES` 显式启用。

API 默认仍为 `EXACT_ENUMERATION`。完整直接业务模型对应 `optimization_model_version=phase1-deterministic-rebalancing-v3`。折扣解锁申请与负责人确认按“当前修订＋输入指纹＋第二阶段精确不可行证明”落库，后续优化运行固化实际使用的确认 ID。只有该确认有效时，`CP_SAT_ENTRY_AND_RATES` 才进入第三阶段；`EXACT_ENUMERATION` 的第三阶段仍显式返回 `INCOMPLETE: DISCOUNT_STAGE_SOLVER_NOT_IMPLEMENTED`，不会被误报为业务不可行。

第三阶段将每条明细折扣编译为 1,000 ppm（0.1 个百分点）网格上的整数变量，遵守人工上下界和锁定。收入有缺口或超额时分别只向上或向下调；若收入已在±1万元容差内、仅综合折扣率未闭合，则在确认边界内允许双向移动。模型使用整数微元和六位小数四舍五入口径，精确表达人数与折后原价收入的乘积、含税转换、当季确认、跨季结转和第一季期初结转；部门/赛道收入目标以及年度/季度综合折扣的 `R00`/`R10`/`R01`/`R11` 口径全部是硬约束。乘法、除法及其中间量同样必须通过 64 位范围证明；无法证明时返回 `INCOMPLETE`。CP-SAT 解仍必须由全量正式内核复算，复算不一致返回 `FAILED`。

不可行记录包含模型哈希、阶段、硬约束组、边界触及、最小剩余缺口或超额的解释性搜索结果；解释性结果不是数学证明本身。若求解器支持 assumption core，另存约束组核心用于定位，但页面不得声称它是唯一业务原因。

## 11. 候选去重、应用和失效

候选先由内核完整复算并通过所有硬约束，再以“参数值＋入口整数＋折扣值＋四季整数人数”的规范哈希去重。收敛结果合并 `scenario_types` 标签，排序按各 profile 的字典序指标和结果哈希。

查看、切换和导出候选均不改变草稿。`应用到草稿` 命令必须：

1. 校验候选、当前修订和输入指纹仍一致；
2. 创建新的组件版本和预算修订；
3. 写入逐项差异、候选来源和审计事件；
4. 使旧计算、其他候选、正式确认和折扣解锁失效；
5. 登记新修订的完整计算作业。

求解器输出不能直接成为发布结果。只有新修订完整复算、正式方案确认和发布检查全部通过后才能发布。

第 1 至第 5 步均已落地：应用请求必须由数据维护人员发起并携带 `If-Match`、幂等键和原因；服务在同一事务中锁定当前修订、复核 `OPTIMAL` 运行与输入指纹、校验逐项差异哈希，再创建差异组件版本、`scenario_application`、子修订和 `CALCULATE_BUDGET_REVISION` 作业。人工计划新生不是调平杠杆，入口行 ID 变化时只重挂原值与锁定状态；同校区内入口结构变化沿用原校区确认，校区合计变化则生成待重新确认的校区入口版本。旧人数、班均、收入、目标闭合、候选、折扣解锁和正式确认从新修订清单移除。

显式撤销只接受仍为当前草稿的应用结果修订。系统从 `scenario_application.source_revision_id` 恢复应用前输入组件，在当前链尾追加 `REVERT_REBALANCING_SCENARIO_APPLICATION` 修订，清除人数、班均、收入、目标闭合、优化运行、折扣解锁、正式确认和候选应用标识，并登记新的完整复算作业。该动作不会删除应用记录，也不会跨过其后的人工修订静默覆盖。

正式方案确认复用同一完整计算流水线，但作业用途标记为 `FORMAL_CONFIRMATION`，执行身份及审计角色为部门预算负责人。四阶段复算后，`phase1-publication-gate-v1` 逐项复核来源冻结、组件齐全、业务确认、入口三层合计、比例边界、计划新生锁定、结果依赖链、人数、班均、收入、折扣和部门/赛道目标闭合。只有零阻断才创建正式确认子修订；发布命令在独立事务中再次执行同一检查并比对确认指纹。

Worker 按 `phase1-full-calculation-v1` 固定顺序执行人数、班均、收入和目标闭合，每一步使用由作业 ID 派生的固定幂等键，并将上一步产生的新修订作为下一步输入。进程在任一步提交后中断时，同一作业重试会重放已完成步骤，不重复创建结果。如果校区合计变化后尚未重新确认，作业以 `INCOMPLETE: CAMPUS_ENTRY_CONFIRMATION_REQUIRED` 暂停；负责人确认后原作业清除阻断并重新入队。作业成功只说明四阶段完成，是否可发布仍以最终目标闭合结果和后续正式方案确认为准。

## 12. 稳定校验码基线

首批实现至少提供以下编码族：

- `SNAPSHOT_*`：分区、刷新链路、对账和字段映射；
- `COMBINATION_*`：维度缺失、重复、四季全零；
- `ENTRY_*`：总值锁定、上下层合计、预留、边界和人工计划；
- `RATE_*`：分母、样本、来源、精度、边界和锁定；
- `HEADCOUNT_*`：计划新生空值、续班去向、分组取整不变量；
- `CLASS_SIZE_*`：未计划开班和不可成班；
- `REVENUE_*`：价格、转换、结转键、跨财年结转和目标差异；
- `DISCOUNT_*`：步长、综合目标和解锁；
- `CONFIRMATION_*`、`PERMISSION_*`、`AUDIT_*`：治理与发布条件。

错误码和页面文案分离；代码一经用于验收或外部集成，不得复用为其他含义。
