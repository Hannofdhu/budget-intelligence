## 交付范围冻结

只交付学校版年度预算基线的完整业务闭环。停止新增纵切、业务概念和优化策略。
允许的收口工作仅包括：将现有 API 能力接入可操作页面、修复缺陷、补齐身份权限、部署运维和既定验收。
不纳入自然滚动预测、滚动补缺、新扩召、另起移动端、视觉重做或额外算法探索。
FY27 继续以定版 Excel 为准，不重建、不调平、不回填修改；真实 BI 抽取与生产部署须单独授权。

正式版最低标准：业务人员不需要 SQL、API 文档或手工粘贴修订 UUID，即可从选择财年到发布、核阅历史完成全部操作。
生产身份不能由浏览器自报角色；正式结果可审计、可备份恢复，服务不依赖开发终端保持运行。

## 完整业务操作路径与当前缺口

以下顺序是交付主路径，不改变服务端各操作的依赖校验。

| 步骤 | 操作与责任 | 已有能力及证据 | 正式版需收口 |
|---|---|---|---|
| 1 | 登录、进入本部门、选择财年或新建预算 | 身份角色模型、年度预算与修订 API | 正式登录与成员配置；预算列表和工作区；不再填 UUID |
| 2 | 维护人员准备历史来源，核对批次并冻结 | 来源抽取、聚合对账、冻结、历史比例参考 API；source snapshot 集成测试 | 来源准备页面、任务进度、错误修复入口；真实来源授权及验证 |
| 3 | 维护目标和业务明细，负责人确认业务范围 | 目标锁定、组合启停、入口范围例外 API | 可填写、核阅、确认的页面；完整维度校验 |
| 4 | 锁定年度入口总值，确定校区分配，负责人整套确认，再下拆 | 校区建议、确定值、确认、明细分配 API | 校区汇总与差额、依据填写、入口明细页面 |
| 5 | 维护续班率、新生占比、边界及锁定，负责人确认边界 | 比例治理与计划新生 API | 参数表、批量校验、角色动作和失效提示；计划新生仍不参与自动调平 |
| 6 | 核对上年春季来源，升年级并建立期初老生版本 | `/budget/opening` 已完成合成浏览器验收 | 接入统一登录和预算工作区，免填身份和修订；真实来源验收 |
| 7 | 维护并确认班均、价格、税务转换、结转、期初结转及折扣 | 资源财务、折扣参数 API | 参数录入核阅和明确确认入口；不能依赖维护人员写 JSON |
| 8 | 执行人数→班均→收入→目标校验，按具体阻断修复 | Worker 全链路、结果版本 API | 统一结果核阅和修复路由；完整明细可追溯，不只显示总额 |
| 9 | 自动调平、比较、应用或撤销，复算 | `/budget/rebalancing`；宽边界求解和 API 黄金样例 | 与上游页面联通；部署环境耗时/超时验证，不能扩大容差 |
| 10 | 负责人正式确认、发布年度基线 | 发布检查页及发布门禁 API | 使用真实身份完成授权预发布演练；全部阻断消除前不得上线 |
| 11 | 查看正式版本、变更和审计；运维备份与恢复 | `/budget/audit`、审计归档能力 | 导航闭环；发布工件、备份恢复演练与运行责任人 |

## 工期估算与日期

这是基于代码盘点的初始工程估算，不是已验证的开发速度，也不是无条件上线承诺。
有效工程工作量估计：

| 工作包 | 估算 | 依据 |
|---|---|---|
| A：已有 API 的页面主路径及修复导航 | 7–10 个有效工作日 | 多个上游业务步骤缺页，但接口和领域计算可复用；避免重做后端 |
| B：正式身份、角色和部门治理 | 3–5 个有效工作日 | 当前只有开发身份，需实际实现适配及验证，不能只改配置 |
| C：部署、备份恢复与发布工件 | 3–4 个有效工作日 | 已有 Docker/CI 基础，但生产配置、恢复演练和发布证据缺失 |
| D：真实数据、业务验收、缺陷回归 | 4–6 个有效工作日 | 复用合成验收，但必须另做真实来源和整条浏览器验收 |

合计约 17–25 个有效工作日，另留 2–3 天缓冲。外部等待不算工程工作量；不假设持续后台运行或已有并行开发团队。

以 2026-09-09 为估算基准，建议把 **2026-10-07 设为功能冻结候选版检查点，2026-10-21 设为正式上线目标检查点**。
这是一条约 4–6 周的条件计划，不是两次检查点到时自动发布：

1. 9 月 11 日前明确部署位置/访问范围，并找到身份与运维接口人；
2. 9 月 16 日前具备测试环境及真实数据窗口的明确授权；
3. 持续提供实施时间，业务方能在每个验收包提交后约两天内反馈；
4. 不新增范围，不出现需要重新决定业务规则的重大数据差异。

若上述前提没有满足，日期保持“待重估”，按关键路径实际延误重排，不把开发版叫正式版。
即使到达目标日，REL-01～07 任一仍 OPEN，也不得上线。
完成 A 的首段完整页面链路并明确 B/C 环境后，用实际耗时重估剩余工作，给出更窄日期区间。
