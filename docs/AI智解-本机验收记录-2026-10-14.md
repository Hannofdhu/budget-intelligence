## 已解决的运行问题

初次真实容器创建成功，但 Pi 终端没有输出。进一步检查发现 Docker/OrbStack 全局响应异常：独立空容器、容器进程查询及后续 metadata 请求也失去响应；数据库只读复核连接超时。

用户明确批准后，使用正常 `orbctl stop/start` 重启 OrbStack，恢复已有预算服务；没有使用强制停机、删除卷、迁移或初始化。底层故障原因尚未定位，不能承诺 Docker 永远不故障。

实测修复了：中文直输被强制屏幕阅读模式吞掉、网关不接受 `developer` 角色、PTY resize 未通知 Docker exec、输出通道失败仍假连接、启动与关闭竞态、进程组信号被拒导致回收中断。相关回归没有放宽检查。

启动现在等待真实终端输出；断流会关闭显示连接而非等待下一次键盘输入；停止使用有界等待与独立清理任务，必要时精确确认容器不存在。无法确认退出时明确 `cleanup_failed`，允许重试，不假报停止。Docker 不可用时不降级为宿主机运行。

## 验收边界

- 这是本机单用户、受控预算只读的 Pi 助手，不是生产多用户授权方案。
- 在线模型目录刷新、联网安装扩展、外部编辑器、系统快捷键及图片/剪贴板协议受隔离和浏览器限制。原生会话与工具机制保留，不宣称所有外部能力完全等价。
- `/resume` 恢复原生对话，不自动复制旧工作区文件；停止不会删除旧工作区或记录。
- 目前只实调主模型；8 个备用模型未逐一调用，自动故障转移已用假传输验证。
- 现有前端大分包警告与 Starlette/httpx 测试弃用警告仍在；没有隐藏检查或把警告称为通过证据。
