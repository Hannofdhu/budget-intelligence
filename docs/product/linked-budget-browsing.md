# 同页预算浏览与生命周期

本轮只改前端交互，不变更计算、参数口径、确认、定版门禁、权限或预算存储。

## 两种操作目的

- 编制预算：明确显示“当前草稿”，沿用五项业务任务及原有保存、确认、计算、调平、发布流程。
- 查看预算：年度入口优先读取已有定版预算，没有定版才打开草稿。显式修订 URL 仍打开该修订，不替换历史版本。
- 有未发布草稿时，“继续修订草稿”进入已有草稿；草稿页可“查看定版预算”。切换不会产生修订或发布。
- 定版修订同时为当前草稿、且用户具有数据维护权限时，可“开始修订”。必须填写原因并点击“创建修订草稿”，复用原 `:derive` 命令、If-Match 与幂等键。成功后进入草稿任务入口。取消不发命令。
- FY27 使用原 Excel 已定版保存值，只读，不开放开始修订，不伪造发布记录。FY28 仍是独立的本机合成试用预算。

## 同一页浏览

- 五步导航一直留在工作区，不因看概览、记录或明细而切换到另一套导航。
- 桌面：汇总在左、明细在右；窄屏上下排列，表格可滚动。
- 点击汇总项，只选中该项并更新明细，不改顶部筛选、不改周围汇总与合计、不更换 URL、不主动滚到下方。
- 再次点击该项或“查看全部”取消选中，回到当前筛选范围的全部明细。
- “筛选此范围”将当前选中项显式写入顶部筛选，再按其他维度浏览。例如：校区 → 筛选此范围 → 按年级 → 八年级。
- 修改筛选后，若选中项仍有数据则保留，若不再存在则取消；旧行依据与分页重置。
- 切换汇总维度、业务步骤、预算版本时，不保留过期行依据。
- 季度收入卡片可以点击筛选；仍显示当前其他维度范围内的四季收入，避免未选季度误显示为零。
- 单条明细的依据/信息在该行下方展开，不弹新页面。FY27 展示原单元格、公式、参数位置；FY28 展示已有收入结果字段与版本来源，不编造 Excel 公式。
- FY27 零值、负数、空值、文本“-”保留。综合折扣仍按合计分子除以合计分母，不平均行比率。

## 验证（2026-10-02）

- 前端生产构建通过。
- `npm test`：4 项浏览状态测试通过（Node 22.18+；项目构建镜像为 Node 24）。
- `pytest tests/unit -q`：222 项通过。
- 本机真实 FY27：全量确认收入仍为 113,004,618.59 元；点击中关村南校区后明细为 76 条，收入为 11,356,851.91 元；固定校区后按年级选择八年级，16 条明细，3,565,183.02 元；继续筛选数学为 4 条，924,644.96 元。
- 原表依据在对应行内展开，保留文本“-”、单元格与参数来源，五项导航和当前 URL 不变。
- 五项业务导航逐项只读回归通过；新校区的 48 条零收入明细保留；无匹配筛选显示空结果并禁用分页，不残留先前选中项；本轮浏览未捕获前端错误日志。
- FY28：年度入口进入定版概览；打开开始修订时，无原因不可提交；取消后仍为原定版修订。未在用户预算库创建测试草稿或重新发布。

## 不在本轮范围

不引入 Grist/ERPNext 依赖，不迁移数据，不改变算法、不新增发布方式，不向 GitHub 上传真实 Excel，不扩大 FY27 的局域网访问权限。当时筛选与点选只保存在页面；2026-10-03 的看板/透视已将全局筛选和布局保存在 URL，刷新与返回可恢复，单元格临时选区不保存。

## 后续决策覆盖（2026-10-02）

用户明确要求 FY27 使用者无需知道历史 Excel 存在。因此上文“FY27 行内依据、参数来源”描述的是先前验收状态，不再作为现行交互要求：对应前台入口和导出中的技术字段已移除，内部追溯校验保留。导出改为数值型 XLSX。2026-10-03 已实现同页看板与多维交叉透视，支持多层行维度、列维度和业务指标；这不代表通用公式或透视回写能力。最新实施结果与验证边界见 [看板与透视 MVP](budget-view-analysis-mvp.md)。
