# 年度预算后三模块交互优化方案

状态：设计方案，尚未实施。依据：2026-09-23 本机 FY28 学校版 R150 页面实看，以及当前页面实现；FY28 数据为本机合成试用数据。

## 1. 一句话方向

沿用年度预算现有的「当前预算 → 一项待办 → 一个主动作 → 返回结果」模式，把调平、发布、审计从三个并列的专业工作台，改成围绕当前预算结果展开的三种情境：**缺口需要处理、方案需要确认、变化需要追溯**。

不改预算规则、角色权限、不可变修订和审计证据；只调整信息架构、默认展示、文案与导航。

## 2. 本轮观察

| 页面 | 当前首屏与实际状态 | 主要割裂点 |
| --- | --- | --- |
| 年度预算 | 五项任务、当前预算状态、一个下一步动作 | 作为视觉和操作基准 |
| 调平方案 | 已定版的 R150 显示「无显著缺口」，却仍把「生成候选方案」放在主按钮；三段杠杆、历史应用回执和空候选区同时出现 | 页面按算法能力组织，没有先判断用户是否需要调平 |
| 发布检查 | 已部分采用五任务导航；R150 已发布、16/16 通过，但仍同时展示核验账本、审签卷宗、修订 ID、指纹和规则版本；直接进入时短暂出现旧式连接页 | 结论已有，已定版状态仍像待操作的审核工作台；加载态不统一 |
| 版本与审计 | 左侧直接列出 150 次修订；英文命令名、内容哈希和 ZIP 归档占据首屏；默认比较 R150 与 R149 | 把完整证据层当成普通用户的默认阅读层 |

## 3. 共用页面契约

1. 三页统一年度预算的顶栏、FY28/R150 状态、间距、卡片、反馈方式；不再各自使用一套全局导航。主导航保留「年度预算」和「预算结果」；调平、发布、审计通过结果页、任务页和上下文链接进入。
2. 顶部始终回答三件事：**现在是什么状态、我还要做什么、操作会影响哪一版**。每个状态只留一个主动作；其余是次级链接或「查看依据」。
3. 全程固定精确修订，不因跳转、刷新或加载而偷偷切到最新草稿。返回链接恢复来源页和筛选；切换版本必须由用户显式操作。已定版修订只读，需改动时先派生新草稿。
4. 默认使用业务语句；命令码、UUID、指纹、求解证明、全量检查和归档放入「技术依据」抽屉。业务结论与证据之间保持可追溯，不删除底层信息。
5. 加载、空数据、失效、不可行、求解未完成、无权限分别有明确状态。禁止把「求解未完成」写成「不可行」，也不把历史回执当成当前可撤销操作。

## 4. 三个页面的建议形态

以下线框中的缺口和候选数字仅用于说明页面结构，不代表 R150 的实际预算结果。

### A. 调平方案 → 「处理预算缺口」

**入口**：预算结果页的「收入与目标」卡片；仅有显著缺口/超额时给出主入口。年度预算任务 4 或任务 5 可显示该待办，但不新增一条必须经过的任务。

**首屏**：一张结论卡说明目标、当前收入、差额、涉及的赛道，以及「可调 / 无需调平 / 先补数据 / 已定版只读」。只有可调草稿才显示主动作「生成方案」。已定版 R150 且无显著缺口时，主动作改为「查看预算结果」；候选区、解锁区和历史应用回执默认折叠。

**生成后**：先展示 1–3 张候选卡，重点只有「应用后差额」「调整了多少明细」「碰到哪些边界」；点击候选再看每条参数的前后值和影响。页面用一条紧凑的「调整顺序」说明系统先调固定入口总值内的入口结构，再并列调续班率与新生占比，最后才可能解锁折扣。算法状态、贡献比例和不可行证明放进依据层。

**动作**：`生成方案 → 对比 → 应用到新草稿 → 完整复算 → 返回预算结果`。应用前明确显示将创建新修订、使哪些下游确认失效；应用后提供可撤销时的显式「撤销本次应用」。若已不可撤销，只显示历史记录与原因，不保留一个灰色的主操作按钮。

**例外**：边界内无解显示「当前约束下没有可行方案」和触及的约束；硬超时或未完成显示「尚未求出结论，可重试」；折扣只有在前两级被证明不可行、且经规定角色申请与确认后才开放。绝不静默放宽边界、步长或容差。

```text
← 预算结果                         FY28 · 草稿 R151
收入距离目标还差 42 万元
先检查可调整空间                 [生成方案]

候选 A：差额降至 0 ｜调整 8 条 ｜2 条触边界
候选 B：差额降至 0 ｜调整 12 条｜无触边界
                [查看差异] [应用到新草稿]
更多：调整顺序 · 求解依据 · 历史应用
```

### B. 发布检查 → 「确认并定版」

**入口**：年度预算的最后一项任务。只有计算结果可用时进入；从发布阻断返回修复页后能一键回到这一步。

**首屏按状态变形**：

| 状态 | 默认内容 | 唯一主动作 |
| --- | --- | --- |
| 有阻断 | 「还有 N 项要处理」；逐项展示问题、影响对象和精确「去处理」入口 | 处理第一项 |
| 全部通过、未正式确认 | 预算摘要、收入与目标、16/16 检查通过；明确确认会完整复算 | 重新计算并确认 |
| 已正式确认、未发布 | 确认人/时间、当前结果和不可逆范围 | 发布年度预算 |
| 已定版 | 「FY28 已定版」和结果摘要；技术检查折叠 | 查看预算结果 |

确认与发布仍是两个独立动作，不能合并成「一键发布」。在确认前完整复算，发布前再次核对输入指纹和硬约束；任何上游改变都使原确认失效。发布检查不可提供忽略阻断或强制发布。发布后只读，需修改则派生新草稿。

完整 16 项检查保留在「全部检查」，但默认只展开阻断项；ID、指纹、规则版本和审签流水进入「技术依据」。直接进入页面的加载态采用同一套顶栏与骨架，取消旧式手填修订 ID 的闪屏。

```text
← 年度预算                         任务 5/5
FY28 可以正式确认
收入与目标差在容差内 · 检查 16/16
                         [重新计算并确认]
查看全部检查 16 项 · 查看本次方案
```

### C. 版本与审计 → 「查看变化记录」

**入口**：每个预算页面右上角的「查看记录」，以及已定版结果页的「查看定版依据」。它是解释当前版本的次级视图，不是和年度预算平级的工作区。

**默认首屏**：以打开时的精确修订为中心，先展示「这次改了什么」「谁确认/发布」「何时生效」。默认和直接父修订比较，但把「R150 相比 R149」明确写在标题中。若无业务值变化，直接说「业务值未变，本次新增正式确认/发布记录」。对用户有意义的里程碑（人工修改、候选应用、正式确认、发布）优先；自动计算产生的连续修订折叠成一次「系统计算」过程。

**按需深入**：版本选择器默认仅列里程碑并提供搜索；「查看全部 150 次修订」打开完整列表。组件级差异、逐行键、审计事件筛选和归档 ZIP 保留在「详细证据」中。英文命令码映射为中文操作名称，原码仍可在详情中复制；内容哈希不占首屏主位。

**浏览路径**：`当前修订概要 → 本次变化 → 操作与确认时间线 → 明细对比/证据归档`。任何版本切换、比较或下载都不改变当前草稿或正式基线。

```text
← FY28 预算结果                    当前：正式版 R150
R150 相比 R149：新增正式确认，预算业务值未变
9月22日 23:35 · 部门预算负责人完成确认

变化记录       [查看本次差异]
确认与发布     [查看证据]
更多：选择其他版本 · 全部修订 · 下载审计归档
```

## 5. 一条完整用户链路

```text
年度预算 → 查看计算结果
  ├─ 无显著缺口 → 确认并定版 → 查看预算结果 → 按需查看变化记录
  └─ 有缺口 → 处理预算缺口 → 应用候选生成新草稿 → 完整复算
                                            ├─ 有阻断 → 精确回到对应任务 → 再检查
                                            └─ 全通过 → 正式确认 → 发布 → 结果
```

## 6. MVP 实施顺序与验收

**第一批：统一入口与状态（P0）**。抽出共用页面壳、修订上下文和返回路径；按状态决定主按钮；修复发布页旧式连接闪屏。验收：已定版、零缺口的 R150 不再引导生成候选；所有深链保留 R150；从任一发布阻断可准确返回处理页再回到检查。

**第二批：压缩默认信息（P0）**。三页只保留结论、下一步和必要数字；算法、全量检查、审计原码进入可展开依据。验收：首屏不出现需要用户理解的 UUID、哈希或英文命令码；屏幕阅读器可读出状态与主动作；窄屏无横向滚动才能看到主动作。

**第三批：完整证据和边界（P1）**。版本里程碑聚合、候选差异抽屉、可撤销性解释和全部技术证据。验收：业务首屏精简后仍可从每个结论追到原始检查、参数差异、操作者和审计归档；`INFEASIBLE` 与 `INCOMPLETE` 文案不同；确认和发布保持两步且分别留痕。

本方案只针对交互重构。真实业务数据接入、预算规则或审批权限变更不在本轮范围内。

## 7. 已定版预算单一入口（2026-09-28）

已按用户确认实施：已定版预算首页与第 5 步直接进入“预算概览”。默认显示预算结果，同页切换“定版记录”；“变化记录”和“查看预算输入”为次级入口。

- 统一入口为 `/budget/workspace?revision=…&section=results`，定版记录使用同一路径的 `view=record`。概览直接嵌入工作区第 5 步，顶部五步导航和预算选择器始终保留；切换前四步只更换工作区内容，返回概览保留筛选。支持浏览器前进、后退和定版记录深链刷新。
- 原 `/budget/publication?revision=…` 在该修订已发布时转入概览的定版记录；未发布修订继续使用原确认与发布流程。发布成功后进入结果概览。
- 原 `/budget/results?revision=…` 兼容转入工作区第 5 步，保留指定修订和记录视图；不再保留独立结果页面框架。
- 严格保留链接中的修订：历史已定版版本不再自动切换为最新正式版。
- 定版记录展示该修订的确认和发布审计事件；当前复核检查按需展开，与历史定版事实分开说明。
- 改造仅涉及前端读取、展示与导航，未变更数据模型、计算口径、确认命令或发布校验规则。

本机只读验收：R150 原计算页入口进入概览；旧发布链接进入记录视图；西直门筛选在切换记录并返回后保留；输入页第 5 步直接返回概览；R139 历史链接保持 R139；390px 窄屏两个视图无页面横向溢出。截图保存在 `output/ui-single-entry/`。未执行确认、发布或预算写入操作。
