# 预算看板与数据透视：MVP 改造方案

日期：2026-10-02；实施收口：2026-10-03。状态：看板和多维透视已完成本机实现；构建、数据核对、自动测试与主要浏览器交互验收通过，下载落盘仍有工具验证边界。

## 1. 结论

不要继续用一张“大而全”的表兼顾所有人。保留同一个预算入口，在“预算概览”中提供两个视图：

- **看板**：业务人员默认使用。全年、季度、校区预算铺开显示，点击后就地查看细分。
- **透视**：数据人员使用。自己选择行维度、列维度和指标，即时重排汇总，选一个单元格查看构成明细。

两个视图读取同一份定版结果，共用年度、版本和筛选范围。任何人都能切换，不新增两套权限或预算副本。看预算不要求知道历史工作簿存在。

原有五项任务导航始终保留。不再从概览跳到另一套外观、导航和版本上下文。“编制/修订”的写入操作仍在原任务流程中；查看、透视、导出不产生预算修订。

## 2. 研究依据：借什么，不借什么

| 对象 | 已核实的交互机制 | 预算智解的取舍 |
| --- | --- | --- |
| Grist 汇总表 | 选择多个分组字段生成汇总，可重新选择字段；数值列默认求和，也能定义汇总公式 | 借鉴自主选维度。指标聚合方式由预算业务定义，不能让比例自动求和或简单平均 |
| Grist 组件联动 | 汇总表可以作为明细表、细分汇总和图表的选择器 | 借鉴同页联动。我们统一全局筛选，明确显示单元格选择范围，避免每块图表偷偷使用不同范围 |
| Frappe Report Builder | 选择列、筛选和排序，保存多个报告；提供分组及 Count/Sum/Average | 借鉴保存“我的视图”，不复制其可直接编辑记录的行为 |
| Frappe Workspace | 工作区可安排图表、数字卡片和快捷入口 | 借鉴一个业务问题一块内容，不把业务看板做成拖拽建站工具 |
| ERPNext 预算报告 | 在独立报告中按财年、业务范围和期间查看预算、实际及差额 | 借鉴“结果查看不等于预算编制”。本项目未接入实际收入时，不凭空展示实际、完成率或预算执行差额 |
| ERPNext 预算修订 | 从已提交预算显式创建新草稿，保存提交后保留历史关系 | 借鉴显式修订入口。ERPNext 会取消旧预算，我们不复制该规则；继续使用本项目不可变修订和原有定版门禁 |

出处：[Grist 汇总表](https://support.getgrist.com/summary-tables/)、[组件联动](https://support.getgrist.com/linking-widgets/)、[Frappe Report Builder](https://docs.frappe.io/framework/user/en/desk/reports/report-builder)、[工作区组件](https://docs.frappe.io/framework/user/en/desk/workspace/blocks)、[ERPNext 预算报告](https://docs.frappe.io/erpnext/budget-variance-report)、[预算修订](https://docs.frappe.io/erpnext/budget-revision)。

研究边界：查阅官方文档、官方开源项目和公开示例；已读取 Grist Investment Research 示例的 Overview/Breakdowns 页面。浏览器后续连接超时，没有完成选择器切换的点击验收，也没有登录 ERPNext 完整运行预算提交链路。上述机制由官方文档支持，以下布局与交互属于针对本项目的设计建议，而非两款产品现成页面的复制。

Grist 的分组汇总不应被描述成已经满足 Excel 的全部交叉透视能力。我们需要自行提供“校区为行、季度为列”的矩阵。不引入 Grist、ERPNext 或另一套分析服务器作为本项目依赖。

## 3. 两个视图的共同外框

```text
预算智解                         FY27 学校版 ▾     已定版
目标与范围 — 入口人数 — 招生参数 — 资源与财务 — 预算概览

预算概览                         [ 看板 | 透视 ]    导出 ▾
赛道 ▾  校区 ▾  产品 ▾  年级 ▾  科目 ▾  季度 ▾       重置
当前范围：全部

                  当前视图内容
```

- 年度/版本切换显式发生；看板、透视切换不改变版本，不丢筛选。
- 五步导航不消失；视图切换是同页操作，不打开另一套全局菜单。
- 已定版是只读状态，不假装 FY27 曾经在本系统审批或发布。
- 浏览器地址保留年度、版本、视图和筛选；返回、前进恢复对应状态。个人视图只保存筛选、维度、指标、排序和布局，不保存一份新的预算金额。
- 同一条明细由财年、季度、赛道、产品、年级、科目、校区定位。业务界面不显示工作簿行号、单元格位置、参数位置或文件哈希。
- 表头写清单位；金额显示可切换“元/万元”，仅影响显示。人次不是去重人数。

## 4. 看板：回答业务人员的问题

默认进入看板。不要让业务人员先配置图表或操作透视字段。

第一屏：

1. 主数字：全年预算确认收入。旁边为预算总人次、综合折扣；年度目标只有该范围存在正式目标时才显示，不能按收入占比虚构校区目标。
2. 四季度柱状图：暑假、秋季、寒假、春季，固定业务顺序、共用尺度，可直接读出收入。
3. 校区 × 四季度收入矩阵：四季、全年合计并排，默认按全年收入排序；所有校区铺开在同一内容区，列头固定。
4. 产品收入横条图：显示主要产品及其占比，完整产品仍可查看，不用大饼图承载大量类别。

交互：

- 点击校区名或产品条，成为显式筛选，整页同步更新，顶部显示“校区：西直门 ×”等可清除标签。
- 点击“校区 × 季度”金额，在同页展开该格的细分/明细，不跳到新页面；展开区明确标出选择范围。上层矩阵保留，便于比较。
- “查看明细”在下方展开；“用透视查看”带着同一筛选进入透视视图。
- 没有该范围数据时显示空状态；真实零值显示 0，不能把零值校区隐藏。
- 默认只呈现预算结果，不显示公式、来源解释或“你应该先确认某组件”的技术语言。

## 5. 透视：让数据人员当场分析

```text
行：[校区] [产品] +        列：[季度 ▾]       指标：[确认收入 ▾]
预设：校区收入 | 产品收入 | 招生人数        保存视图    导出

校区 / 产品             暑假       秋季       寒假       春季       全年
▾ 西直门                ...        ...        ...        ...        ...
  智慧空间              ...        ...        ...        ...        ...
  智慧伴学              ...        ...        ...        ...        ...
合计                    ...        ...        ...        ...        ...

所选单元格：西直门 / 秋季 · 确认收入 ... 元           清除选择
构成明细：赛道、产品、年级、科目、人数、确认收入
```

MVP 能力：

- 行维度从校区、赛道、产品、年级、科目中多选，可移动顺序；增删后立即汇总，无需“重新生成预算”。
- 列维度选择季度或一个业务维度；不选列维度时退为普通分组汇总。不能重复把同一维度同时放在行、列。
- 指标支持确认收入、含税业务收入、老生、新生、总人次，以及有合法分子分母的综合折扣；收入/人数可多选。
- 分组展开/折叠、排序、行列小计和总计；固定行标题与列头。缺少组合显示“—”，已有组合金额为零则显示 0。
- 选中单元格只筛选构成明细，单元格周围的透视表不变。再次点击或清除选择恢复全部当前范围明细。
- 数字区域框选后显示求和、非空数值个数、最小/最大值；平均仅对有业务意义的数值字段开放，不用于汇总比例。
- 原始明细/透视切换；直接复制数值到 Excel；命名保存个人视图。跨年度应用视图时清理无效筛选并显示具体被清理的值。
- 导出当前透视表或当前范围全部明细，导出范围与页面一致，不只导出当前分页的 25 行。选中单元格时显示“导出所选明细”，明确区别于全范围导出。

不做：通用公式编辑器、透视结果回写、整份电子表格编辑、任意 SQL、多人同时编辑透视单元格、预算结果手动覆盖。实时透视指“即时重组同一份结果”，不是随时改变定版预算。

## 6. 数值与汇总的底线

| 指标 | 汇总方式 / 约束 |
| --- | --- |
| 预算确认收入 | 汇总季度确认收入；不能把当季业务确认收入 + 递延收入当成全年确认收入 |
| 业务收入 | 汇总含税业务收入，标签明确“含税”，不能与确认收入混用 |
| 老生、新生、总人次 | 按季度求和；全年是人次合计，不是去重学员人数 |
| 综合折扣 | 汇总业务收入 ÷ 汇总原价收入；分母为 0 时不显示比例 |
| 续班率 | 如有完整基数，按 (续班人次合计 − 专项班续班人次合计) ÷ 原班人次合计；只有参数百分比而没有完整基数时，保留明细值，不给出合计比率 |
| 考核新生占比 | 如有完整字段，按业务新生人次合计 ÷ 三分之二出勤口径招生人次合计；不能用预算计划新生/预算总人次冒充 |
| 预算新生结构 | 如展示计划新生 ÷ 预算总人次，单独命名“预算人数中新生占比”，不替换原参数或考核口径 |
| 最低班均、单价、当季确认比例 | 明细参数，默认不求和；最低班均不能当作实际班级数或实际班均 |

年度业务范围只有 238 行，季度明细有 952 行。年度金额等重复在每季记录中的字段不能直接对 952 行求和。所有视图共用指标规则，不能各写一套聚合公式。

工作簿：项目根目录 `【智慧学习部】FY27预算拆解（1.13亿）-备份.xlsx`，滚动表，业务行 2–239。保持保存值，不重算源工作簿。

| 季度 | 旧导出“当季业务结转（元）” | 旧导出“转入下季（元）” | 真正计入该季的确认收入 |
| --- | --- | --- | --- |
| 暑假 | AW：FY27暑-Q1结转(税后) | AY：FY27暑-代入Q2结转(税后) | AX：FY27-Q1总结转(税后) |
| 秋季 | BN：FY27秋-Q2结转(税后) | BP：FY27秋-代入Q3结转(税后) | BO：FY27-Q2总结转(税后) |

| 春季 | CV：FY27春-Q4结转(税后) | CX：FY27春-代入FY28Q1结转(税后) | CW：F27-Q4总结转(税后) |

前两列相加是 FY27 当年业务产生的不含税收入，包含延后确认到 FY28 的部分，不包含 FY26 转入。

```text
当季业务确认收入合计         94,386,954.19
递延至下季收入合计           18,093,050.15
二者合计                    112,480,004.34
+ FY26 春季转入（AG）         7,847,731.60
− FY27 春季转出 FY28（CX）    7,323,117.35
= FY27 全年预算确认收入      113,004,618.59
```

滚动表各行公式关系：AX = AW + AG；BO = BN + AY；CF = CE + BP；CW = CV + CG。全年确认收入看 AX、BO、CF、CW 的合计，也与 W 全年保存值对齐。新导出已把两列改名为“当季业务确认收入（不含税，元）”“递延至下季收入（不含税，元）”，金额和公式未改。

验收场景：

1. 业务人员不打开编制表、不看来源信息，能回答“全年收入多少、哪个季度最多、某校区每季多少”。
2. 数据人员无需导出，能把“校区 × 季度”换为“校区 → 产品 × 季度”，再切换收入与人数。
3. 选择某个校区秋季收入，构成明细金额之和与该格一致；返回不丢筛选、不换版本、五步导航仍在。
4. FY27 全范围确认收入始终为 113,004,618.59 元，季度明细 952 行，业务范围 238 行；没有年度字段重复累加。
5. XLSX 的金额、人次、比例是数值；比例是 0.9 配合百分比格式，不是文本“90%”；空白、0、负数和“-”分别保留。
6. 保存个人视图、排序、筛选、复制、导出、切换布局，都不会增加修订或调用预算写入/确认/发布命令。
7. 没有实际收入、完整比例基数或校区目标时，不编造完成率、汇总续班率或分配目标。
