# 第一期：年度预算基线 PRD

状态：业务规格已冻结，可进入详细技术设计  
适用范围：FY27 学校版年度预算，后续财年复用同一模型并更换参数版本  
目标单位：万元；底层收入计算保留元级精度

## 1. 产品结论

第一期交付一个独立的“年度预算”工作区。它以学校版部门及赛道目标为硬约束，以固定财年入口总值为起点，通过预算组合、入口分配、续班率、新生占比、整数人次、班均、价格、折扣和结转节奏形成年度预算基线。

系统计算值是默认基线，用户只能修改明确开放的业务参数，不得直接改写中间计算结果。任何正式预算必须同时满足智慧伴学、智慧空间和部门合计目标，完成所需确认并通过全部发布校验；草稿可以保留不闭合结果，但不能带异常发布。

## 2. 一期目标

- 将 Excel 中的年度预算拆解逻辑转成可复算、可追溯的版本化流程。
- 区分系统建议、业务确定值和正式发布值，避免保存即生效。
- 让入口初始值的形成依据可见，并保持财年入口总值严格不变。
- 用统一考核口径生成续班率、新生占比的历史参考值和目标参数。
- 以整数人次执行班均和收入校验，不通过静默补人制造可行结果。
- 在预算缺口或超额出现时，生成可解释、可撤销、确定性的候选调平方案。
- 为第二期自然滚动预测发布不可变的父版本及完整参数、锁定和审计快照。

## 3. 一期范围

### 3.1 纳入范围

1. 学校版部门及赛道目标维护与锁定。
2. 年度预算组合识别、启用、关闭和确认。
3. 财年入口总值、校区入口建议、校区入口确定值和整套确认。
4. 入口班默认范围及全维度人工纳入、人工排除。
5. 校区以下入口明细按历史占比下拆，新产品先预留，整数尾差按最大余数法处理。
6. 续班率、新生占比的历史参考、去校区回退、人工指定、上下限和锁定。
7. 老生、新生、总人次的四季推演及分组最大余数法取整。
8. 班均、学费原价、结转节奏、明细折扣率和综合折扣目标参数。
9. 业务季度收入、季度总结转和年度总结转。
10. 入口分配、比例参数及折扣率的分级调平。
11. 草稿应用、正式方案确认、发布、版本比较、审计和回滚查看。
12. 用户角色与成员配置。

### 3.2 不纳入范围

- 实际收入接入、财季状态、定版实际和季度终值预测。
- 退班率回退、预计后续新增、预计剩余退班和自然滚动缺口。
- 滚动补缺方案。
- 续班去向迁移；续得老生继续保留在来源预算行。
- 新生、扩科、召回构成以及暑秋、寒春联报率的参数、推演、校验和人工覆盖。
- 预算组合合并或合班组。
- 直接修改系统中间结果、强制发布、自动扩大容差或隐藏精度。
- 技术栈、部署架构、接口协议、性能 SLA；这些在技术设计阶段另行确定。

## 6. 端到端业务流程

### 6.1 创建年度预算草稿

用户选择财年并创建草稿。系统记录父版本、创建人、创建时间和角色快照。若同财年从已有版本派生，默认继承比例参数锁定；跨财年默认不继承，显式复制时必须按完整参数键重新校验。

### 6.2 锁定目标与源数据

FY27 正式目标为：智慧伴学 3,700 万元、智慧空间 7,600 万元、部门合计 11,300 万元。每个目标允许绝对误差为正负 1 万元，赛道之间不得互相抵消。

学校版部门与全部赛道目标由数据维护人员按正式依据整套导入并锁定，不允许部分锁定，也不增加单独审批；最终完整目标随年度预算正式方案由部门预算负责人确认。目标尚未整套锁定时不得计算、调平或发布，目标变化必须派生新修订并使全部下游结果和确认失效。

比例参数生产计算读取“智慧学习部指标汇总宽表”唯一最新 `dtdate = MAX(dtdate)` 分区，入口历史占比从“智慧学习部学员花名册”计算。正式参数冻结前，花名册刷新与宽表下游快照必须属于同一截止链路并完成分子、分母对账。数据维护人员负责最新分区质量；系统不再叠加其他数据质量阻断，但必须保存数据集、快照日期、任务批次和对账结果。

### 6.3 确认预算组合

历史预算组合由上一财年成熟季节的有效招生人次识别。新产品、新校区、新增科目等无历史组合由人工启用；关闭历史组合必须填写原因。预算组合六个维度都必须是具体值，不支持通配。

数据维护人员保存组合草稿后，由部门预算负责人执行独立确认。新增或关闭整个校区会使整套校区入口确认失效；只改变现有校区内部组合时，保留校区入口确认，但使该校区明细入口下拆及后续计算失效。

### 6.4 确认整套校区入口分配

每个财年先由数据维护人员录入并锁定非负整数财年入口总值，记录变更原因、操作人、时间和角色快照。财年入口总值不增加独立审批环节，随整套校区入口分配一起由部门预算负责人确认；未锁定时不得生成或确认整套校区入口。

修改或解锁财年入口总值后，整套校区入口确认、入口明细分配、人数、收入、班均、候选调平方案、折扣率调平解锁和正式方案确认全部失效并重新计算，旧值、旧锁定和旧确认继续保留审计。同一用户兼任两类角色时，也必须分别执行锁定与整套确认。

新校区、无可用历史校区先由业务方人工设置建议值并填写原因，形成无历史校区建议预留。预留合计不得超过财年入口总值。

有可用历史数据的校区按以下公式生成入口建议理论值：

`校区入口建议理论值 =（财年入口总值 - 无历史校区建议预留合计）× 该校区上一财年入口班业务新生人次 / 全部有历史校区上一财年入口班业务新生人次`

上一财年入口班范围使用当时确认的默认范围及人工纳入、排除规则，分子、分母先汇总再计算占比。全体校区均无历史时，全部建议值由业务方人工设置。

教室资源和销售资源不进入系统隐含权重，而是业务方判断校区入口确定值及资源硬边界的依据。业务方维护校区入口确定值；与建议值不同的校区必须选择原因类别并填写说明。

整套校区入口建议值必须严格汇总到财年入口总值。建议值只作为参考，不替代校区入口确定值及其整套确认。

无历史校区人工建议预留必须为非负整数。剩余整数入口总值按历史占比得到有历史校区建议理论小数后，先取整数部分，再按小数余数从大到小分配尾差；余数相同时按稳定校区 ID 排序。系统保留理论值、整数建议值和尾差归属，相同输入必须得到相同结果。

系统实时展示：

`校区入口总量差额 = 财年入口总值 - SUM(校区入口确定值)`

系统不自动补偿其他校区。只有全部必填依据完整且差额严格为 0 时，部门预算负责人才能一次性确认整套校区入口分配。确认后不可直接修改；变更必须派生新草稿并重新确认。

### 6.5 下拆入口明细

入口班默认范围为该财年第一个季节编码且年级为七年级，统计“业务新生人次”。人工纳入、排除必须填写财年、赛道、校区、产品、年级、科目六个具体值，优先级为人工排除高于人工纳入、人工纳入高于默认规则。

校区以下的产品、年级、科目同级构成入口明细组合。存量组合使用上一财年入口班实际业务新生人次占比；新产品比例由人工确定，并先从校区入口值预留。剩余入口额度按存量组合历史占比缩放，最后使用最大余数法分配为整数，确保明细严格汇总到校区入口确定值。新产品比例合计超过 100% 时禁止保存。

每个入口明细组合同时保留入口初始值、默认软边界和业务资源硬边界。自动建议的常规范围默认为入口初始值的 80% 至 120%，但任何建议都不得突破教室、销售等资源形成的绝对硬下限和硬上限。入口初始值为 0 的组合不能套用比例边界，必须先显式填写计划值、硬下限、硬上限和原因，才可进入自动入口分配候选。

### 6.6 形成比例参数

续班率：

`(SUM(续班人次) - SUM(专项班续班人次)) / SUM(原班人次)`

新生占比：

`SUM(业务新生人次) / SUM(招生人次(三分之二出勤口径))`

两项比例均先汇总分子、分母再相除，不平均明细比率。分母为 0 视为无历史数据。默认使用上一财年同赛道、产品、年级、季节、校区实际值；续班率还必须匹配续班关系。精确维度样本不足默认门槛 30 时，仅去掉校区重新汇总；仍不足或为新产品则必须人工指定。系统标记精确历史、去校区回退、人工指定三种来源。

续班率参数必须满足：

`0% ≤ 确认下限 ≤ 当前确认值 ≤ 确认上限 ≤ 100%`

用于反推新生人次的新生占比参数必须满足：

`0% ≤ 确认下限 ≤ 当前确认值 ≤ 确认上限 ≤ 99.99%`

100% 新生占比只允许作为入口分配或人工计划已经明确新生绝对人次后的计算结果，不得作为反推输入或自动调平参数。

上下限由数据维护人员录入、部门预算负责人独立确认。数据维护人员和部门预算负责人均可按完整参数键锁定、解锁或修改并锁定；被锁定参数继续参与计算，但自动调平跳过。批量锁定保存为明确参数键清单且整批原子成功或失败。

### 6.7 推演并取整四季人次

第一季入口新生来自入口分配。后续每季先按上一季来源预算行及续班关系计算老生理论值，续得老生留在来源预算行，年级按续班关系变化，科目不变。

老生理论人次大于零时，按以下公式反推当季新生理论值：

`新生理论人次 = 老生理论人次 × 新生占比 /（1 - 新生占比）`

老生理论人次为零时，系统不使用比例反推，必须由数据维护人员或部门预算负责人按完整季节预算明细填写并锁定非负整数计划新生人次，同时记录原因。即使业务不计划招生，也必须显式填写并锁定 0 人；空值表示尚未处理，不能自动解释为 0。负数或小数禁止保存，系统不得静默取整。该人工计划不需要独立审批，但必须纳入部门预算负责人的正式方案确认，也不进入最大余数法。入口分配或人工计划已经明确新生绝对人次的行，以该人数作为输入；新生占比只作为 `新生人次 / 总人次` 的计算结果，该行不参与新生占比自动调平。新生和老生均为零时，新生占比结果为不适用。

在“赛道＋校区＋季节”取整组内，老生、新生分别汇总理论值并四舍五入得到整数总量，再按最大余数法分配到明细。入口分配和已锁定计划新生人次属于定量整数，先从该组整数总量中保留，不参与余数排序；最大余数法只在剩余反推型小数人次之间分配尾差。余数相同时使用稳定内部 ID 排序。取整后重算实际续班率和新生占比并展示取整差异，系统不得通过静默补人消除差异。

### 6.8 执行班均校验

班均按赛道和产品设置。FY27 初始值：

| 赛道 | 产品 | 班均 |
|---|---|---:|
| 智慧伴学 | 普通、云帆 | 24 |
| 智慧伴学 | 白金、云帆白金 | 15 |
| 智慧空间 | 普通、云帆 | 20 |
| 智慧空间 | THINK、高端小班 | 12 |

校验粒度为“季节＋赛道＋产品＋入口属性＋年级＋科目＋校区”，使用取整后老生加新生的整数总人次。0 人表示该季未计划开班；1 人至班均减 1 人为不可成班；达到班均即通过。四季均为 0 的已启用组合必须关闭。

不可成班只能在固定财年入口总值、已锁定收入目标和确认比例边界内通过重新分配入口或增加招生目标解决；仍不可行时关闭组合。系统不提供合并、忽略异常或带异常发布。

### 6.9 计算收入与综合折扣

`折后学费 = 学费原价 × 明细折扣率`

`业务季度收入 = 整数总人次 × 折后学费`

`业务季度税后收入基数 = 业务季度收入 ÷ 预算含税转换系数`

FY27 学校版 Excel 使用的预算含税转换系数为 `1.06`。该系数作为财务参数随参数版本冻结，不得作为代码中的不可追溯常量。

`当季确认税后收入 = 业务季度税后收入基数 × 当季结转比例`

`跨季结转比例 = 1 - 当季结转比例`

`跨季结转税后收入 = 业务季度税后收入基数 × 跨季结转比例`

`季度总结转 = 当季确认税后收入 + 上一季跨季结转税后收入`

`年度总结转 = SUM(四个季度总结转)`

FY27 Q1 的“上一季跨季结转”是 FY26 春季甩入的税后结转，作为资源与财务参数版本中的期初结转输入；FY27 春季跨季结转输出至 FY28 Q1，不计入 FY27 年度总结转，但必须随发布基线保留供下一财年引用。

预算测算中的业务季度收入是含税金额，必须先按预算含税转换系数转为不含税基数后再结转。该规则不得套用于滚动预测的实际字段：`预计结转收入` 和 `财季结转收入` 已是不含税金额，不得再次除以 `1.06`。

班均、学费原价、预算含税转换系数和结转节奏统一进入完整资源与财务参数版本。数据维护人员维护参数草稿、来源证据和变更原因，部门预算负责人执行独立确认；权限管理员不审批业务参数。同一用户兼任两类角色时，保存草稿与确认参数版本仍为两个独立留痕动作。

班均、学费原价、预算含税转换系数和结转节奏是锁定参数，不参与自动调平。综合折扣率按原价收入加权：

`SUM(总人次 × 学费原价 × 明细折扣率) / SUM(总人次 × 学费原价)`

分母为 0 时为不适用。计算使用完整精度，显示可四舍五入，但发布判定不使用显示值。

### 6.10 生成并应用候选调平方案

调平顺序：

1. 在不改变财年入口总值的前提下，先调整入口在校区及明细组合间的分配结构。
2. 续班率与新生占比作为并列第二杠杆。
3. 前述杠杆达到已确认边界后仍不可行，才允许部门预算负责人显式解锁折扣率调平。

比例参数候选包括平衡 50/50、留存侧 70/30、招生侧 30/70 三种收入贡献软目标。每类参数内部使用等百分点水位法，按 0.01 个百分点步长推进，触及确认边界或锁定后退出。定量新生人次行的新生占比是只读结果，不进入水位法；计划新生人次也不是自动调平杠杆，系统不得生成或改写。多解依次选择贡献份额偏离更小、最大单条调整更小、总调整量更小、稳定内部 ID 更靠前的解；相同结果去重。

明细折扣率只能按 0.1 个百分点调整，且部门、赛道、年度和季节综合折扣率与对应目标的绝对差异不得超过 0.05 个百分点。任何层级不可同时满足时报告不可行，不扩大容差。

候选方案只供比较。数据维护人员应用方案后形成可撤销的草稿差异，不自动确认；部门预算负责人对最终完整方案执行独立正式确认。

### 6.11 发布年度预算基线

只有部门预算负责人可以发布。发布动作生成不可变的年度预算基线，冻结目标、组合、入口分配、参数版本、锁定、整数人次、收入、校验、确认和审计快照。发布后修改必须派生新草稿，不能覆盖原版本。

## 7. 依赖失效规则

| 变化 | 必须失效或重算 | 可以保留 |
|---|---|---|
| 学校版目标整套变化或解锁 | 人数之后的目标校验、候选方案、正式方案确认、折扣解锁和发布检查 | 不受目标影响的输入组件及旧目标版本、旧结果和审计 |
| 财年入口总值修改或解锁 | 整套校区入口确认、明细下拆、人数、收入、班均、候选方案、正式方案确认、折扣解锁 | 旧值、旧锁定、旧确认和历史版本 |
| 新增或关闭整个校区 | 整套校区入口确认、明细下拆、人数、收入、班均、候选方案、正式方案确认、折扣解锁 | 历史版本 |
| 调整现有校区内部组合 | 该校区明细下拆及全部下游结果 | 整套校区入口确认 |
| 任一校区入口确定值或依据变化 | 整套校区入口确认及全部下游结果 | 原确认版本 |
| 比例值、边界或锁定变化 | 参数版本、人数、收入、班均、候选方案、正式方案确认、折扣解锁 | 旧参数与审计记录 |
| 计划新生人次修改或解锁 | 受影响人数、收入、班均、候选方案、正式方案确认、折扣率调平解锁 | 旧值、旧锁定与审计记录 |
| 班均、价格、预算含税转换系数、折扣目标或结转节奏变化 | 参数版本及受影响的收入、班均、候选方案、正式方案确认、折扣解锁 | 未受影响的人数中间结果；发布前整体复算 |
| 应用其他候选方案 | 当前草稿计算结果、正式方案确认、折扣解锁 | 所有候选及版本比较记录 |
| 任一上游变化导致收入越界 | 原候选结果、正式方案确认、折扣解锁 | 草稿保存与查看 |

## 8. 发布硬约束

以下任一条件不满足，草稿可以保存但不得发布：

- 智慧伴学、智慧空间、部门合计分别未进入目标正负 1 万元容差。
- 两个赛道之间存在用超额抵消缺口的情形。
- 正式参数源刷新链路未对齐、源分子分母未完成对账，或仍处于“等待宽表快照”。
- 预算组合、整套校区入口、比例参数边界或最终方案缺少所需确认。
- 财年入口总值未由数据维护人员锁定，或资源与财务参数版本未由部门预算负责人确认。
- 校区入口确定值合计不严格等于财年入口总值。
- 启用组合缺少全部具体维度、新产品入口比例或班均等必填参数。
- 存在未处理的不可成班组合、四季全零的已启用组合或预算公共维度重复。
- 比例参数违反数学边界、确认上下限、精度或锁定约束。
- 老生理论人次为零且无入口分配等新生绝对量时，计划新生人次为空或尚未锁定；显式锁定的 0 人属于有效值。
- 综合折扣目标在完整精度下超出 0.05 个百分点容差。
- 调平在既定步长、边界和整数约束下不可行。
- 存在未处理的批量操作失败、跨财年锁定复制异常或依赖失效项。
- 当前用户不具备部门预算负责人角色。

## 9. 审计与解释要求

每个可编辑或确认动作至少记录：对象、对象键、修改前值、修改后值、系统计算值、人工覆盖值、原因、操作人、操作时间、草稿/参数版本、当时角色。正式参数还记录来源数据集、快照日期、来源批次、对账结果；候选方案还记录输入版本、目标贡献、实际贡献、边界转移、不可行原因和确定性择优结果。

任何页面不得只显示最终值而隐藏系统基线、人工差异或阻断原因。

## 10. 与第二期的交付契约

第二期只能选择已发布年度预算基线作为父版本。第一期至少向第二期提供：

- 年度预算基线 ID、财年、发布时间、发布人及角色快照；
- 完整预算组合与稳定内部 ID；
- 四季整数人次、收入、结转和年度目标；
- 参数版本、来源快照、人工覆盖和比例参数锁定；
- 入口范围规则、校区入口分配、班均、价格、折扣和结转参数；
- 全量审计和发布校验结果。

第二期不得回写或覆盖这些内容，只能继承并在独立滚动版本中引用。
