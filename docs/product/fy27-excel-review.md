# FY27 Excel 定版回看

## 入口与边界

- 本机入口：`/budget/workspace?archive=fy27&step=5`，年度选择中提供 FY27。
- 五步导航沿用年度预算布局：目标与范围、入口人数、招生参数、资源与财务、预算概览。
- 本视图使用原 Excel 保存值，只读，不调用预算写入、计算、确认或发布命令，不替代 FY28 当前版本。
- “已定版”是用户确认的历史事实，不伪造系统发布时间、审批人、修订编号或门禁通过状态。2026-10-02 起，前台不再要求使用者了解历史工作簿。
- 输入源为项目根目录的 FY27 Excel；显式导入时核对文件，页面运行时只读 PostgreSQL 中的已核对档案。首次提取 `output/fy27-shadow/source-cells.json` 保持不可变；导入的当前文件哈希不同时，必须经过授权的等价核对，并由 `accepted-source.json` 固定当前文件、新旧提取的完整字节哈希和业务指纹。未知新哈希、提取缺失或篡改时拒绝导入，不覆盖数据库中的已接受数据。
- 原 Excel 与提取数据受 Git 忽略规则保护；不在前端静态资源或源代码中内嵌业务数据。

## 映射

- 滚动表 A/B/C/D/E/F/G：赛道、产品、是否入口、年级、来源年级、科目、校区。
- W：全年确认收入；AE：年级错位后的春续暑基数；AG：期初不含税结转；AH：最低班均。
- 业务维度和四季字段按精确业务表头定位，缺失或重复表头拒绝读取。最初汇总收入在 AX、BO、CF、CW；当前插列后使用 AX、BO、CG、CY 的保存值，与全年列以分为精度独立核对。重复命名的辅助列仍逐个校验已知位置。
- 续班率、新生占比、价格、折扣、结转节奏按原辅助键关联参数表，保持 Excel 首个精确匹配语义。空值、文本“-”和数值零分别保留。
- 页面比例不平均各行比率。综合折扣使用业务收入合计 / 原价收入合计；明细参数直接读取原值。
- 全年人数是季度人次之和，不表示去重学员人数。
- 原通知目标仅用于历史对照，不能作为 FY27 重新调平要求。
- 零值行不删除；最低班均补新生公式、负数结转保留为历史依据，不放宽系统新预算的校验。

## 本机访问

历史接口沿用本机试用启用限制、身份及部门权限，另外检查由 Vite 代理从连接地址覆盖写入的客户端地址。局域网真实地址、缺少该标记的请求均拒绝。现有 FY28 合成试用仍可按原方式共享。

如以后希望同事查看真实 FY27，需另行明确授权范围和部署方式，不自动扩大共享。

## 当前 Excel 接受与历史身份（2026-10-09）

- 用户授权以项目里现有 FY27 Excel 为准。本次布局新增 BZ、CR 两列；238 个业务单元、952 条季度明细的业务值、辅助键及完整参数表与原提取等价。滚动表 24,487 个公式经共享公式展开和插列坐标还原后均相同。
- 本次新提取保留当前真实单元格坐标、保存值和公式，不保存或重算原 Excel。`sha256` 继续代表已确认预测绑定的不可变预算基线身份；`source_file_sha256` 单独代表当前原文件字节，不修改 P16 或既有 FY28 冻结来源。
- 本机采用流程为 `analysis/fy27_shadow/adopt_source.py`，默认只核对，显式 `--apply --actor ... --reason ...` 才保存单独提取和接受记录。未知后续改动不会自动通过。原 `extract.py` 已禁止覆盖首次提取。
- `source-cells.json` 及早期影子核对报告保留为冻结历史证据；旧影子核对 CLI 不应再绑定当前已插列 Excel，也不用于当前页面读取。

## PostgreSQL 历史数据档案（2026-10-09）

- `historical_budget_archive` 保存完整业务读模型 JSONB、当前 Excel 字节、新旧提取字节、来源接受记录及各自哈希。JSONB 用于页面与计算读取；原字节用于恢复及完整核查，保留数值、空值、文本、负数、原公式与坐标，不重算原文件。
- 这是独立的、部门隔离的只读历史档案，不伪造年度预算系统的发布记录。复用现有 PostgreSQL 连接、迁移和不可变触发器，数据库拒绝更新或删除已导入档案。
- 三个模块统一沿用历史接口读取：FY27 查看预算、FY27 达成预测、FY28 下一年预算。请求只选业务模型和校验元数据，不读取 Excel、提取文件或大体积原始档案，也没有静默文件回退。数据库缺档案返回 404，校验失败返回 409，连接不可用返回 503。
- `scripts/import_fy27_archive.py` 默认只核对；`--apply --actor ... --reason ...` 才在专用本机数据库中事务导入。相同部门、年度和文件哈希重复导入幂等返回；内容冲突拒绝覆盖。导入后在提交前核对完整来源字节和数据库读取结果，失败回滚。
- 原预算身份哈希保留，当前原文件字节哈希独立存储，既有预测和下一年草稿的版本、来源和结果不改写。后续 Excel 编辑不会自动改变在线数据，需要再次显式导入。
- 迁移前保留 PostgreSQL 自定义格式备份于受 Git 忽略的 `output/fy27-db-migration.*/before-migration.dump`。这是一份本机迁移备份，尚未配置异地备份或定时备份；数据库持久化本身不等于完整生产运维。
- 本次只迁移历史预算来源，预测与下一年预算的既有追加式版本账本仍在 `output/forecast-ledger`、`output/next-year-ledger`，未迁移或重写这些账本。真实 FY27 本机访问限制保持不变。
