# 全产品明细导出拆列验收

日期：2026-11-16。规范入口为 [DESIGN.md 第 6.3.1 节](../../DESIGN.md#631-明细导出采用独立字段)。

## 问题与实现

前端为了紧凑，把 SKU 身份、指标及说明放在同一格；部分表格直接提取这个单元格的文字写入 Excel，导致展示结构被当成分析数据结构。另一些表虽然提供了结构化投影，但数值中仍保留了不适用标记，或沿用了浏览时的零值默认。

本轮将当前结构化预算表格的导出改为原字段投影。共用 `budgetDetailExport.ts` 管理 SKU 五维列；参数、指标、状态、备注和来源分别成列。`QuarterlyBusinessTable` 可以单独定义导出业务字段及指标，前端跨季阅读与定位编辑不变。公共版本元数据也将财年、模块、版号、预览状态、基准及来源字段分别保留；描述文字不作为解析数据的依据。

有效零、未知、不适用、无经营基础、未保存、待重算及非法输入分别保留。数值列不混状态句子；必要的原始输入证据另列。未因拆列请求新数据、重新计算预算或改变版本、确认、定版规则。

新增架构检查 `detailExportCoverage.test.mjs`：结构化预算 `ActionTable` 必须有显式导出数据，分页实例必须同时声明导出列和行投影。该检查用于阻止以后重新引入展示文字回退；实际字段正确性仍由工作簿读回与业务测试核实。

## 两轮独立审核

第一轮发现并修复：FY28 非法未保存输入混入数值列；历史续班率不适用标记未拆状态；预测明细沿用浏览默认零值。预算分析明细、历史逐季及跨季导出均同步修复。

第二轮发现辅助比例编辑表的同类非法输入边界，已修为数值、输入状态和原始输入三列，编辑和批量操作本身未改。最终复核未发现剩余阻断问题；第二轮独立回归分别为 270 / 270、18 / 18 通过。
