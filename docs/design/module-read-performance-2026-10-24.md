# 预测与预算编制：读取体验和性能修复

## 范围与根因

本轮仅修改读取、导航与缓存生命周期，不改变预算参数、计算公式、定版规则、已保存版本或 FY28 编制基准。

1. 预测页把只读加载与保存、生成预测等写操作共用导航锁，读取期间点击别的模块会被拦截。
2. 模块链接原先整页重载，丢失已读取结果；开发环境重复挂载也可能重复发起请求。
3. FY28 当前版本每次重新读取约 200 MB 文件台账、验证历史；目录还会读取/复制全部 FY27 来源快照。
4. FY28 当前读取、历史读取和目录串行执行，目录的耗时也占用页面忙碌状态。

## 实现

- 三个预算模块的共用导航使用现有应用壳切换，不建立第二套预算流程。保留真实链接、修饰键打开新页、未保存修改提示和写操作保护。AI 及原有编辑工作区保留原生页面离开保护，避免绕过未发送提问/未保存内容的确认。
- 进入产品后只以 GET 预读已保存预测、预算编制、来源目录和默认趋势；不会查询 BI 刷新、试算、创建、保存或确认版本。
- 内存读取缓存按身份、部门、角色、完整资源路径区分，路径包含财年和精确历史版本。30 秒内复用；最多保留 5 分钟显示快照，重新进入后后台核对。预算内容不新增写入 localStorage/sessionStorage。
- 并发订阅共用一次请求。离开页面取消本页订阅，不中断其他页面的预读；共享网络读取有 60 秒截止时间。保存/确认等命令失效相应缓存，旧请求不能回填覆盖新结果。
- 权限错误清空相关会话缓存与页面数据；普通读取失败诚实显示错误，保留仍可查看的已保存结果，不伪称成功刷新。
- 缓存命中直接显示保存结果；无缓存时保留安静的占位，导航始终可用。不显示常驻的“读取预测中”、趋势读取进度文字。
- FY28 来源目录独立读取，不占用当前结果的就绪状态。后台响应不得覆盖输入中的未保存内容；相同版本的后台核对不关闭已展开工具。
- PostgreSQL 预测缓存以部门、会话工厂和不可变台账链头为依据，每次读取检查链头，追加/确认导致重新验证；写路径仍在原事务内完整验证。
- FY28 文件读取在原文件锁下比较所有台账文件的名称、inode、大小、修改/变更时间；变化后重新执行完整指纹和版本链验证。缓存仅存读取投影，所有对外返回均深拷贝。
- 冷台账验证移出事件循环；复用同一次已验证的规范化事件摘要，避免无意义的重复哈希，不删除任何验证。
- 判断新来源只读取最新已确认预测，目录复用按完整版本/确认状态标识的轻量来源选项。不会更换预算本身已绑定的预测。
- 页面卸载与新操作推进请求代次，迟到历史响应不能修改其他模块地址、清除新操作状态或覆盖新保存结果。

## 本机性能观测

均为同一份保存结果的 GET，不是“更新预测”或预算试算速度；单次观测，不作为跨机器 SLA。

| 接口 | 修复前重复读取 | 修复后预热读取 |
| --- | ---: | ---: |
| FY27 当前预测 | 4.152 秒 | 0.316 秒 |
| FY28 当前预算 | 22.205 秒 | 0.778 秒 |
| FY28 版本目录 | 25.682 秒 | 0.734 秒 |

服务重启后仍需首次冷校验：本次测得预测 6.247 秒、FY28 13.784 秒、目录 3.703 秒。冷校验不是零耗时，但不会锁住模块切换；已完成预读后进入模块直接呈现保存结果。新增台账或内容变化必须重新验证，不能为速度跳过完整性检查。

## 验证

- 浏览器先复现：预测读取未完成时，点击 FY28 仍停在预测并提示“当前操作完成后再切换”。
- 修复后：初始预测及预算占位期间均可立即切到其他模块；从定版预算进入后，两边预读结果直接呈现，趋势也没有重复读取进度。
- FY28 临时填写未保存备注，仅用于离开保护验收：模块点击出现“修改未保存”，继续编辑保留备注；浏览器后退同样被保护。随后清空临时备注，恢复第 23 版、改动 0 项，未保存任何版本。
- 实测仍是 FY27 预测第 26 版、FY28 第 23 版，FY28 基准仍是 FY27 已确认第 20 版；定版预算金额与改造前一致，具体金额保留在本机验收证据中。
- 前端全套测试、生产构建；后端存储和相关 API 合同测试、Ruff、严格类型检查；真实 PostgreSQL 隔离 schema 的台账与趋势缓存集成测试均执行。
- 覆盖缓存复用、身份/财年/历史隔离、取消订阅、超时、晚响应、跨进程追加、文件篡改、确认事件失效、不可变触发器、校验失败恢复及导航保护。
