# AI智解：对话工作区实施与验收

日期：2026-10-23。范围：用结构化对话替代 AI智解主入口的原生 Pi 终端；不改变其他预算模块及其计算、保存、确认和定版规则。本记录不是此前品牌迁移的两轮审核记录，也不宣称新增功能经过了未实际执行的独立子代理审核。

## 设计取舍

直接参考用户提供的 Codex 截图中的“左侧历史—中央消息—底部输入—折叠执行过程”关系。沿用预算智解当前暖白、深墨、陶土橙、功能字体和「解构之窗」Logo，不复制 Codex 编程项目树或文件修改卡。

已实现：

- 新对话、标题搜索、置顶、按本地日期分组、重命名、归档与恢复；URL 可定位单段对话，但链接本身不授予读取权限。
- 自动保存已发送的消息与回答，刷新和后端重启后回看；继续提问恢复本段对话原有模型上下文，不重新发送历史问题。
- 多行输入、Enter 发送、Shift+Enter 换行和输入法组合态保护。页面内切换对话保留各自未发送的文字，离开页面提醒；不承诺刷新后仍保留未发送文字。
- 回答逐步显示，支持 Markdown、代码和表格；表格使用共用复制／Excel 导出，完整对话可导出 Markdown。导出标明停止、未完成和错误，不把残缺结果导成完整成功回答。
- 真实执行过程按工具调用呈现、默认折叠；可以停止回答，保留已收到的文字和过程。失败不伪装成功，不自动重复提交问题。
- 从业务入口带入的已保存版本、筛选范围与来源链接归属于该对话；回看旧对话时不换成当前页面或最新版本。

未添加附件上传、语音、模型选择、跨设备账户同步和开发代码变更卡。当前模型继续遵循原配置，实测为 `glm-5.2`，未更换为 OpenAI，也没有新增密钥。

## 持久化与边界

对话展示记录保存在本机 AI 运行根目录的 `chat-history/<浏览器身份摘要>/<对话标识>.json`；模型上下文位于该对话独立的原生 Pi session。临时 Docker 进程退出后，两者仍保留。对话历史目录不挂入模型容器。

当前是“本机保存、当前浏览器身份”的机制。使用 HttpOnly、SameSite=Strict 的浏览器身份 cookie；清除浏览器数据可能无法找回身份，不声称账户级历史。旧终端记录原样保留，但因未能可靠核实其浏览器归属，不自动导入新历史，也不将其他浏览器的记录展示给当前使用者。

对话存储使用私有目录、受限文件权限、无跟随符号链接的读取及原子替换。运行任务、锁和停止操作同时绑定浏览器身份与对话 ID；即使两个浏览器选用了相同 ID，也不能相互读取或停止任务。创建和发送使用独立请求标识，响应丢失后先回读，不自动重复调用模型。

模型仍在 `--network none` 容器中，只接入既有受限模型／预算桥接，预算 GET-only、产品源码不可访问、宿主凭证不进容器。未新增浏览器到任意 Pi 指令、宿主 shell、任意路径或外网的通道。答案禁止执行原始 HTML、脚本和自动加载外部图片；私有推理和签名不进入可见消息。

## Pi 协议适配

依据当前固定版本 [Pi 1.2.0 官方 RPC 文档](https://github.com/earendil-works/pi/blob/v1.2.0/packages/coding-agent/docs/rpc.md) 实现 `pi --mode rpc`，不是抓取 ANSI 终端文本。

- 使用 stdin/stdout 的 LF JSONL 与命令 ID 关联，保留中文、emoji 和 Unicode 行分隔符。
- `prompt` 的确认仅代表接收；文本增量用于逐步显示，`message_end` 校正最终段落，`agent_settled` 才作为本轮结束依据。
- 浏览器只能请求产品封装的发送和停止；运行层仅使用 `get_state`、`prompt`、`abort`。
- 前端生成中约 800ms 回读持久化消息，空闲约 10 秒；这是逐步显示，不是浏览器 SSE 的逐 token 传输。不在完整性缺失时编造完成状态。
- 停止或进程退出失败显示真实状态，并要求重试停止；未确认清理前禁止继续发送／归档。后端重启后的遗留“回答中”会标为已中断。

主要实现：`AiChatPage.tsx`、`AiChatMessage.tsx`、`aiChatApi.ts`、`aiChat.css`、`packages/ai_agent/chat.py`、`packages/ai_agent/rpc.py` 和 AI API 路由。原终端接口及组件兼容实现保留。AI 页面独立懒加载，Markdown 依赖不进入其他预算页的首屏加载路径。

1. 实际发送并收到 `glm-5.2` 回答；设置标题和置顶，刷新后消息仍存在。
2. 让模型记住非业务代号「橙窗37」，刷新并重启 API 后继续提问，实际返回原代号；不是模拟上下文。
3. 停止准备中的回答，确认显示“回答已停止”、保留问题；归档后不可发送，恢复后可以继续。
