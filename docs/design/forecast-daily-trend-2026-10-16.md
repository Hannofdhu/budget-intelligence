# 全年预测：每日自动更新与结转收入趋势验收

日期：2026-10-16。状态：本地实现、自动化测试及独立代码审核通过；真实本机首次补跑已成功生成 P20 草稿，已完成桌面与窄屏主要交互验收。没有自动确认、改动定版数据或替换 FY28 基准；本记录不代表未来准点执行或远端发布。

## 实现范围与统一设计

- 在“全年总览”下、四个大指标上方增加“结转收入趋势”，不新增工作台、预算编辑流程或独立图表依赖。
- 复用现有 `BudgetDataSection`、`ActionTable`、设计令牌及原生 SVG；字号、容器、焦点与响应式布局沿用统一规范。图表按实际容器宽度布局，不把桌面图整体缩成不可读的小字。
- 默认全年，可切换暑假、秋季、寒假、春季；历史范围为近 30 天、近 90 天、全部历史。期间及历史范围是单值阅读配置，不是 SKU 多选筛选器。
- 深绿虚线表示“预计结转收入”，蓝灰实线表示“截至当日实际结转收入”；同时提供文字图例，不仅依赖颜色。纵轴单位为万元，横轴为北京时间快照保存日期，日期间距与真实时间间隔一致。
- 趋势属于全年全部业务，不受下方 SKU 筛选和分组影响；四个原有大指标、季度达成、明细及已有筛选行为保留。

## 每日更新与运行边界

- 复用同一个本地 Worker 进程、现有观远取数、预测计算与 PostgreSQL 不可变版本台账；内部日任务消费者与普通任务分开领取，避免普通任务的 I/O 等待挡住日调度，不新增第二套后台服务。
- 按 `Asia/Shanghai` 每天上午 09:30 到期，包括周末。后台按轮询周期检查，不宣称硬实时秒级调度。
- 默认关闭，需显式本机启用标记；本机启动器可读取被忽略的 `output/local-trial/forecast-daily.json`，严格限定为 `enabled` 布尔值的小型 JSON，不接受符号链接。显式环境配置优先。
- 仅允许已启用的本机试用环境、绑定部门及 `budget_acceptance_*` 数据库。后台使用独立服务身份，不借用浏览器 Cookie，不伪造人工审核或确认记录。
- 需要已有人工建立的预测父版及一致的定版预算指纹；沿用本次实际读取父版的季度状态和参数，不依据日历自行更改季度状态。
- 电脑、数据库及本地服务需保持运行。关机、休眠或服务停止不能保证 09:30 准点；恢复后只补跑当天已到期的一次，不为错过的历史日期补造快照。
- 部门、财年和上海日期生成稳定任务及请求身份；数据库唯一约束、跨进程抽取锁、现有台账幂等及父版比较共同防重复。锁与台账写入锁使用不同命名空间，避免保存时嵌套死锁。
- 人工刷新与自动取数互斥，发生冲突时明确提示或有限重试，不打断正在执行的人工刷新。人工修改仍走既有版本比较与保存流程，不覆盖其已提交内容，不清除未保存编辑。
- 失败采用有限重试和安全错误记录；过期租约可恢复，旧执行尝试不能覆盖新租约结果。数据库临时不可用时退避继续；已保存台账结果而尚未登记任务成功时，重放同一请求，不重复取数或新增版本。

## 快照、确认与失败保护

- 自动更新成功只追加一个 `DRAFT` 预测版本，冻结当次来源快照、参数、计算结果、数据截至日期和来源证据；不自动确认。
- 自动计算未达到既有正式可用条件时，在追加版本前失败，保留原可用预测。人工更新原有行为和预测计算规则不因日调度而改变。
- 不修改任何既有定版预算、历史版本、确认事件或定版规则；不替换 FY28 已引用的预测基准，也不代填 FY28 经营目标。
- 来源验证标记明确区分自动验证与人工操作，不把服务身份包装成人工批准。人工修订复用自动来源快照时，生成方式按该版本实际创建者识别，不误标成新的自动更新。
- 页面读取趋势和自动更新时间均为鉴权后的只读查询，不触发观远取数、预算保存或确认。趋势读取失败不清空其他预测内容；同一精确版本下切历史范围失败时保留上次成功范围并明确标注。

## 已配置本机的维护入口

这不是新电脑初始化流程。已有本机身份、数据库和观远授权的环境，在 `output/local-trial/forecast-daily.json` 保存 `{"enabled":true}` 后，从项目根目录依次执行：

```bash
.venv/bin/python scripts/local_trial.py restart-api
.venv/bin/python scripts/local_trial.py restart-worker
```

这两项重启不执行 seed、迁移或数据恢复。关闭时改为 `{"enabled":false}` 后重启相同服务；显式 `BUDGET_FORECAST_DAILY_ENABLED=false` 优先于本机文件。文件不随 Git 分发，不要把启用配置误写进默认示例环境。状态可通过已有身份读取 `GET /api/v1/forecasts/fy27/schedule`，读取本身不会触发取数。

## 趋势数据口径与历史截止

- 预计线读取当时已保存预测的全年或季度最终结转收入；实际线读取该版冻结来源中的季度累计实际结转收入，不用预测金额、定版预算或按零计的兜底值冒充实际。
- 保存日期和数据截至日期分别显示：前者来自版本创建时间并转换为上海日期，后者保留来源 `as_of`。同一天默认取截止范围内最后一版成功、完整预测；全部日内版本仍在原台账中保留。
- 指定历史版本时先按精确版本序号截止，再按日选点；近 30／90 天窗口止于所选保存版本日期，不混入之后的预测，也不以今天的日期替换历史时间。
- 实际缺失、明确失败的财务校验及无效金额不补零；全年实际仅在四季实际均已提供时求和。真实零值和负数保留，原始金额以精确十进制传输，元转万元仅用于展示及导出。
- 未取得的观察不连线，不插值、不补造历史日期。只有一个保存日时展示真实数据点；历史不足或没有可用快照时如实说明。
- 不扩大或改变已有看板中“未知实际按 0 展示和汇总”的既定规则；趋势需要区分真实实际观察与该展示兜底，原始缺失继续可追溯。
- 可通过图表点击、日期滑块键盘操作或趋势数据选择保存日；显示所选版本、确认状态、生成方式、保存时间和数据截至日期，并进入原有精确版本详情。忙碌或有未保存编辑时，不绕过原有切版保护。

## 复制、导出与紧凑缓存

- “查看趋势数据”按需展开，不常驻第二张工作表。复用同一 `ActionTable` 工具栏提供一键复制与 XLSX 导出，范围与当前期间、历史窗口和精确版本截止一致。
- 传输保留金额数值类型、负数、缺失说明和完整来源元信息；不是对图形截图或已格式化标签重新计算。实际浏览器复制与下载验收另由主代理补记，不以合成测试代替现场证据。
- 趋势缓存只保存已完成完整台账及快照指纹校验的精简投影，不保留原始 `source_data`，不写数据库或建立第二套预算存储。
- 每次读取检查不可变台账链头，新增版本和确认事件均使旧投影失效；缓存身份同时绑定部门、会话工厂及基准指纹，最多保留 8 个条目。返回深拷贝，调用方不能污染缓存。
- 错误基准、冷读完整性失败或数据库错误均明确失败，不在新链头下冒用旧缓存。首次冷读和新链头后的校验仍随台账历史规模增长，不宣称永久恒时查询；热读切范围及历史截止无需重复读取全量来源快照。
