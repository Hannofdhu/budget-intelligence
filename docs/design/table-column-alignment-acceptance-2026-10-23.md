# 全产品表格列对齐修复与验收

日期：2026-10-23。范围：共用表格及各模块的表头、编辑控件、只读值、勾选列和跨季表头。沿用现有视觉规范，不改预算数据、计算规则、保存/定版规则或复制导出的数据范围。

## 原因

1. 表头和数据格已有数字右对齐，但数字字段是一个限宽的块级 label。单元格的 `text-align` 不会把这个块推到右边，输入框内数值也不会自动继承正确对齐。1440px 实测班均输入框距单元格右边约 360.22px，财务输入框约 40.75px。
2. 各页面历史样式的选择器优先级不同，通用数字类会被本页的表格规则覆盖，比例编辑表、结果表存在同类风险。
3. 部分模块按列序号设置对齐。状态表头与正文采用不同规则；增加维度、多级表头和重排后容易出现不一致。
4. 跨季表通用的“每行第一格固定”规则误作用于第二层表头的首个数字格。横向滚动时，该格会被当成业务列固定在左边，而对应数据继续滚动。

## 修复与防复发约定

- `ActionTable` 增加统一的 `data-budget-table` 样式边界，保留各页面原类名、DOM、滚动容器和快捷键；既有透视表也使用相同边界，不替换其选区系统。
- 复用 `budget-cell-number`，补充 `budget-cell-text`、`budget-cell-center`。表头和对应数据格按同一业务角色对齐，不靠列序号判断字段类型。
- 限宽数字字段容器靠右；框内数值右对齐并用等宽数字。比例单值及范围控件共用相同右端锚点。普通表单、搜索、备注和校验说明不受此规则影响。
- SKU 五维身份内容始终左对齐；独立入口、参与预算、调平锁定和选择列居中。
- 跨季分组标题居中，底层数字表头右对齐；数字表头保留纵向吸顶，但不再误固定到左边，层级低于固定业务表头。
- 保留原生 table 及独立横滚，不使用整页固定列宽、缩小字号或裁切输入来掩盖问题。
- 已纳入 `DESIGN.md` 第 6.1 节。

## 实测结果

- 1440px：财务及班均输入框右边距统一为 12px；多行范围中财务75个、班均7个、招生50个可见数字编辑控件均通过对齐检查。入口及SKU独立勾选列抽样中心偏差为0。

- 校区跨季表横滚至右侧后，20个指标表头与首行数据的列右边界偏差全部为0；第二层首个数字表头的 `left` 为 `auto`。
