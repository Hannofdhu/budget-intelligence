## 1 实施边界

- 查看预算：FY27 第 1 步的 SKU 区块。
- 下一年预算：FY28 第 1 步的 SKU 区块。
- 共用 `BudgetDataSection`，集中维护区块标题、数量、业务操作槽、卡片及表格外壳；语义视觉参数在 `budgetTokens.css` 中。
- `ActionTable` 仅新增可选的搜索工具槽和表格滚动容器。未使用新参数的表格保持原结构和键盘顺序；未迁移其他步骤或季度表。
- 两页标题统一 18px / 600 / 26px，表格 14px，卡片圆角 16px、宽屏内边距 24px、窄屏 16px（以根字号 16px 为基准）。
- 搜索、快捷键、复制和导出集中在工具行，工具行不随表格内部滚动。FY27 保持只读；FY28 保留原新增和勾选处理。
- 两页既有业务列保持原样：FY27 为入口、全年结转收入（元），FY28 为入口、参与预算。初次实施遗漏了身份维度展示一致性，不能将此遗漏归为应保留的业务差异；纠偏记录见第 5 节。

## 2 本轮修复

1. 移除对应 SKU 区块对旧 `.history-section h2` / `.ny-section h3` 标题样式的依赖，以共用角色控制标题和间距。
2. 修复旧全局表单样式覆盖新搜索框、按钮和分页的问题；触控 44px 规则使用同级语义选择器，避免被普通样式盖过。
3. 表格单元格滚动定位避让固定导航和底部保存栏。新容器在 Ctrl / Cmd + Home / End 时先滚内部边缘，再显示焦点；旧容器行为不变。

## 5 身份维度一致性纠偏

初次 M1 仅统一外壳，FY27 保留两组维度列，而 FY28 仍拼成“校区 / 业务”。规范将分组展示写成“建议”，M1 和 V01 又只强制标题、容器，测试因而没有拦住这一漏项。用户明确前者更易读，并要求业务列保持原样。

本次仅将两页第 1 步 SKU 的身份表头和单元格抽为 `SkuIdentity.tsx`，统一“校区 / 赛道 / 产品”及“年级 / 科目”，保留校区、年级主行和其余字段次行。既有收入、入口、勾选、新业务标记及其处理均不增删；其他步骤不迁移。规范同步升级为必须项，并要求跨页比对身份列，而非仅检查共用外壳。

- 前端全套 `npm test`：510 / 510 通过，0 跳过，退出码 0；类型检查和生产构建通过。上方 505 项为初次样板记录。
