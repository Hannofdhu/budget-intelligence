# AI智解：并行会话、队列与提醒验收

日期：2026-10-24。本次仅补齐用户要求的后台完成提醒、侧栏实时进度和自动排队，沿用统一设计规范、现有 Pi／模型及只读预算边界。未更换模型、增加密钥或放开容器网络。

## 已实现

- 本机共享 3 个执行名额。第 4 个及后续问题进入 FIFO 队列，名额释放后自动启动，不需要重复发送。单段对话仍不允许同时发起两轮问题。
- 排队与运行由后端管理，页面切换不影响任务。可以取消排队，取消发生在模型提交前；已运行任务保留停止回答功能。慢启动不会持有整个队列的锁，不能让另一段排队任务无法取消。
- 侧栏同步本浏览器的所有对话：排队位置、回答中、真实工具执行状态、完成、失败和取消。活动时约每秒读取一次历史摘要，空闲约 5 秒；隐藏标签页放缓读取，回到前台立即同步。不声称逐毫秒推送。
- 后台结果到达时显示正文流内的可点击提醒，并以“未读”文字和标签页计数持续保留。通知中心汇集所有未读结果；收起一条提醒不会丢掉其他结果。
- 当前对话实际展示结果、靠近消息底部且页面可见后，按本轮回答 ID 标记已读；迟到的旧已读请求不能吞掉新结果。已读状态在后端对话记录中保存，刷新后不重新出现。
- 窄屏打开通知中心时收起历史列表，打开历史列表时收起通知中心。通知中心独立限高滚动，不覆盖正文；低矮视口仍允许纵向滚动到输入区。

新增 `POST /api/v1/ai-agent/conversations/{id}/read` 仅修改该浏览器自己对话的已读标记，沿用精确 Origin、HttpOnly cookie 和本机访问保护；没有预算写接口。队列位置仅返回数量，不暴露其他浏览器的对话标识、标题、内容或工作区。

## 故障与恢复约定

- 并发已满是一种可等待的状态，不作为模型失败；其他模型／环境异常仍如实失败，不无限重试。
- 执行名额由现有运行层统一校验，旧终端也占用同一上限，不能靠队列绕过。
- 进程退出确认后再释放名额；退出失败仍要求重试停止，不以“完成”掩盖清理异常。
- 已接收但未调用模型的队列保留问题和接收时间。后端重启后，浏览器回到 AI 工作区时恢复该身份下的待执行队列；不会扫出其他身份的私有历史。
- 已运行或提交状态不明的任务在重启后标记中断，不自动重发。排队、失败和取消也在对话导出中明确标记，不能伪装完整回答。
- 一次最多接收 128 项等待任务、每个浏览器最多 32 项；未接收的超限问题不追加为已发送消息，输入保留。该上限不是允许 128 项同时调用模型。

## 验证证据

### 自动化

在现有 AI 单元／契约测试基础上新增可控并发运行测试，验证：

- 3 项运行后第 4／5 项等待，顺序自动启动，峰值不超限，消息重试不重复调用。
- 排队取消不调用模型；停止和失败释放名额；慢启动期间其他排队任务仍可取消。
- 同一 ID 的不同浏览器仍隔离，不能读取、取消或标记他人的结果已读。
- 已读幂等、旧回答的迟到已读不能吞掉新回答；刷新后未读保留。
- 服务关闭保留未启动队列；恢复只执行未启动问题，不重放已运行问题。
- 工具开始事件在长工具返回前立即保存，侧栏不等待工具结束才显示进度。
- 未读提醒按回答 ID 去重，较旧摘要不能覆盖新状态或丢失其他对话；取消／排队导出与模型回答明确区分。

## 范围与限制

通知目前是 AI 工作区内提醒、未读中心和标签页计数，不是操作系统弹窗；未请求系统通知权限。离开 AI 模块后任务继续，重新进入查看未读；关闭本机后端不会继续执行模型任务。没有新建外部定时任务或云端通知服务。

Safari、真实移动软键盘、屏幕阅读器和长期高负载未作本次完整验收，不宣称全平台认证。本地产品生效，未推送 GitHub。验收对话保留并归档，不永久删除。
