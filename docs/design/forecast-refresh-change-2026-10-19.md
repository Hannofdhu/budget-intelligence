# 全年预测：自动更新修复与趋势收敛

日期：2026-10-19。沿用 [统一设计规范](../../DESIGN.md)，只调整现有预测链路和同一张趋势图。

## 自动更新故障与修复边界

- 当时运行的 worker 先加载了旧版 `store`，更新代码后直到次日任务执行才懒加载预测路由。新趋势模块引用新增函数时，旧内存模块不包含该函数，产生导入错误。
- 原日志只有 `attempt_finished`，通用错误也没有阶段或异常类型，不能从旧日志直接还原原始堆栈。上述原因通过“旧已加载模块 + 新磁盘依赖”的隔离复现、进程与代码更新时间比对，以及新进程的真实只读 dry-run 共同定位；不是把观远故障作为默认原因。
- worker 启动时预加载既有预测依赖，初始化不完整就明确失败。部署更新仍须重启 API 和 worker，不支持运行中混用新旧代码。
- 保留现有每天北京时间 09:30 的调度、来源检查、计算、幂等键、租约及有限重试；没有新建调度服务或第二套计算。未知程序错误不盲目自动重试。
- 修复后的运维重试仅限当日、当前部门、指定失败任务和预期错误码，且不能超过原有尝试次数限制。成功或过期任务不能被重置，过去失败日期不补造快照。
- 每次尝试保留安全的阶段、错误码、异常类型、关联编号、耗时、结束时间、结果及重试决定。未知旧失败仍标为未知，不追填猜测的异常类型。不会记录原始来源行、SQL、凭证或任意异常文本。
- 成功更新只追加未确认的预测草稿。既有预测快照、确认记录、定版预算、FY28 引用及规则不变。

## 同图“看总量 / 看变化”

- 默认“看变化”，切换“看总量”仍在同一张图内；不查询来源、不重算、不保存，不改变当前选择日期。
- “看总量”展示两条原始金额线，共用包含零的纵轴，单位万元。
- “看变化”分别减去当前历史范围首个保存日的各自原值，明确标注基准日期，单位万元。两条线的零点不是两种收入金额相等。
- 图下“比上版”使用该保存版本的精确直接父版，不是图中上一个保存日。同日多次更新、父版在历史窗口之外，也按真实直接父版比较。先用原始金额相减，再转换为万元。
- 首版、缺失父版、父版计算不完整和未知实际分别明确说明，不能补零或跳过真实父版寻找一个更早的完整版本。
- 保留季度、历史范围、保存日选择、历史完整预测入口，以及原有趋势明细的一键复制和导出。导出保留原值，并附直接父版引用及增减。
- 自动更新状态收敛成一行，失败原因和诊断信息按需展开，避免重复警告常驻。
