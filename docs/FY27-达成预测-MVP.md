# FY27 达成预测

## 交付边界

在现有本机产品中新增“达成预测”，独立于年度预算编制。FY27 已确认的只读定版档案作为比较基准；不重新导入年度预算命令，不构造年度预算发布事件，不修改原文件、952 条定版明细或 FY28 版本。

这一桥接仅用于用户已经认可的 FY27 历史定版档案。FY28 及之后仍须引用系统正式发布的年度预算基线，不能通过本功能绕过年度预算发布检查。

本次为本机 MVP，真实数据仍只允许本机访问。局域网权限、统一身份、生产 PostgreSQL 预测存储和灾备不在本次交付中；不能把本机确认称为内网正式上线。

## 默认状态

由用户于本次会话明确确认，不根据日期推断：

| 季度 | 状态 | 使用方式 |
| --- | --- | --- |
| 暑假 | 已定版 | 冻结实际人次及不含税财季收入 |
| 秋季 | 开放招生 | 预测新增、剩余退班和季末终值，重算全季度收入 |
| 寒假 | 未来未开始 | 按有效续班率、新生占比及价格等参数连续推演 |
| 春季 | 未来未开始 | 按上一季度预测终值继续推演 |

默认不调平。缺口为定版预算减预测；正数显示缺口，负数显示超额。一万元展示阈值只影响“无显著缺口”标签，不能改数或成为预测确认阻断。

## 用户路径

1. FY27 查看预算 → 达成预测。
2. 生成预测：一次只读提取最新完整 BI 分区，冻结该分区、来源批次、字段口径、参数和结果；固定预测规则自动沿用，不逐条人工确认。
3. 查看四季预算/预计、全年预计收入、达成率和缺口；选择赛道、校区或年级查看明细。
4. 如有数据阻断，展开明细并由数据维护人员确定完整维度映射；系统不按相似校区名合并。
5. 有必要时调整开放季度的校区预计新增、新生退班和老生退班合计，填写原因；系统分配到明细并生成新的草稿。
6. 数据检查通过后，由部门预算负责人确认预测。后续刷新或调整生成新版本，旧确认不会沿用。

不提供自动补缺方案，不显示相对上一次滚动的收入差异，不将未算完的年度金额或达成率显示为零。

## 自主准备的试用预测

以下记录保留最初试用版本的交付边界。2026-10-06 起按下节“固定预测规则”执行，历史试用版本本身不被改写。

用户于 2026-10-05 要求先交付可用版本，授权自主解决剩余试用默认值，不逐项询问。默认值仅是可修改的试用假设，不是已核实的业务事实，不改变原预算或正式确认规则。

- 暑假部门合计始终用完整冻结实际；缺少对应明细的预算行保持未知，不把预算或零冒充实际。下钻包含未知明细时不显示伪造合计。
- 秋季已有实际的业务：当前分类基数，加预计新增，减预计后续退班，得到季末终值，再按整季财务参数重算收入。
- 秋季没有来源的原预算范围：暂沿用该范围原预算季末人数，标记“预算值暂估”；仅用于试算，不能作为零事实声明或实际数据。
- 原预算未覆盖但有来源的业务：作为独立预测范围。沿用已确认的校区关系与产品关系，其他维度不变；无对应关系的完整维度保留原名，不做相似度匹配。金融调整单独保留，不凭金额生成招生人次。
- 独立业务的秋季预计后续新增默认逐明细为 0，可手动修改；不覆盖该校区其他预算业务的新增分摊。
- 寒假、春季：原预算范围沿用原预算参数、承接前季预测人数。独立范围有同季度、同赛道、同产品、同年级预算样本时，续班率先汇总前季基数乘明细率，再除总基数；新生占比为总新生除总招生。没有样本则暂时保持上季人数、不预计新增，标记“规模暂沿用”，不填造 100% 续班率。
- 独立范围财务参数仅使用明确填写或同季度同赛道同产品完全一致的模板，不对不一致参数静默取均值。
- 所有试用假设保存在新的预测版本，原快照和旧版本不变。试算完整与正式可确认分开：可以展示全年预计与缺口，但试用版本不能正式确认。

前端一键“准备试用预测”；结果页直接展示四季、全年和各业务维度。展开“试用假设”可编辑独立范围的单价、折扣、当季确认比例、续班率、新生占比和开放季度新增人次；保存后生成新预测，不改原预算。

## 固定预测规则（2026-10-06）

用户明确要求：当前正在生效的暂定规则作为固定规则沿用，无需人工手动确认。规则与本次预测确认分开，固定规则不再构成单独的试用/审批门槛。

- 已定版季度始终使用冻结实际；原始未对应实际明细继续保持未知。根据 2026-10-06 用户确认的展示规则，实际未知收入和人次在前端明细、维度汇总和导出中按 0 计，不改来源值，也不使用预算收入或人次替代。
- 开放季度按当前人次加预计新增、减预计剩余退班计算季末人数，再按完整季度参数重算。
- 原预算范围没有当前来源时，沿用原预算季末人数作为预测估计，不冒充实际。
- 原预算未单列业务独立预测；沿用已保存的明确维度对应关系，不进行相似名称匹配。
- 独立业务开放季度后续新增默认 0，保留已保存的人工调整。未来季度优先使用已保存参数；需要自动参考时，仅使用同季度、同赛道、同产品、同年级的加权人数比例。没有适用样本时沿用前季人数，不新增新生，不伪造 100% 续班率。
- 独立业务财务参数优先沿用已保存值；自动模板只取同季度、同赛道、同产品完全一致的参数，不对不一致值取平均。
- 最小历史样本默认 30，继续逐层汇总分子、分母后计算退班率。按校区、分类汇总取整，再以稳定完整键的最大余数法分配。
- 不自动调平，不改变年度定版预算，不自动正式确认预测结果。

服务端使用 `fy27-fixed-rules-v1` 记录规则版本。首次固化以当前预测的原快照及现有参数生成新草稿，不刷新 BI、不改旧事件；后续生成、刷新和保存自动应用固定规则，人工已保存参数优先保留。页面不再展示“固定规则 / 自动沿用”横条，计算方法放在页尾“预测怎么算”；参数按需调整，不提供逐规则确认按钮。

取消的是规则层面的人工确认，不是数据校验：缺失冻结实际、未知维度、无财务参数、负人数等仍按原规则处理。本次预测的正式确认仍要求负责人权限、当前版本、正确预算基准及无数据阻断；刷新或修改后仍形成新草稿。

### 零预算空组合自动核验（2026-10-07）

用户明确认可：确认预测结果不应要求逐项担保来源中不存在的零预算空组合。新增 `fy27-empty-budget-actual-v1` 确认策略，只作用于固定规则草稿，不修改预算计算公式、定版预算或原始实际。

以下条件必须同时成立，才将该季度的 `FINALIZED_ACTUAL_MISSING` 从阻断改为信息记录：

- 完整冻结来源证明有效：分区日期一致、抽取前后版本稳定、原粒度覆盖及财务逐键/部门勾稽通过。
- 仅限原预算业务行；老生、新生、总人次、期初结转、折前收入、业务收入、当季收入、确认收入、转出结转均为显式数值 0。空白、`-`、布尔、非零、负值或正负抵消不符合。单价和单人折后学费不是金额贡献，不要求为零。
- 全部缺失组合都不含冻结结转输入，前季预算结转也为零；按完整键及已保存映射逐条检查，不能通过结转正负净额为零放行。原始来源存在、但被映射到其他业务的行不符合。
- 同季度完整来源收入、人次与冻结部门合计精确一致；已知预测明细按保存的六位金额精度汇总后，也与部门收入、人次精确一致。
- 没有任何其他数据阻断。非零预算缺失、无效实际、未对应真实业务、合计不一致等继续阻止确认。

原缺失记录的 code、维度、message、raw null 和显示为零的适配均保留。INFO 的含义是“符合确认豁免”，不是“实际已核验为零”；核验条件和勾稽合计保存于该版 `confirmation_checks`，在页尾“预测怎么算”中可追溯。

规则启用以相同冻结快照和原参数生成新草稿；不刷新 BI，不改写旧事件或旧确认。预算负责人仍需亲自确认本版预测结果；状态、版本、预算指纹、权限及幂等检查继续生效。页面和存储层同时防止 `ready=true` 与剩余 BLOCKING 冲突时被错误确认。

## 来源与计算

- 宽表最新 `dtdate`：同一预测版本只取同一个分区，抽取前后核对来源版本和任务批次，不允许截断预览或跨刷新混用。
- 冻结实际收入：`SUM(财季结转收入)`，已不含税，不再次除以 1.06。收入明细中的财务归属使用“财年＋财季”，课程归属使用“业务归属年＋业务归属季度”，不使用空的“季节财年”列。
- 当前招生基数：逐完整维度校验新生、老生退班分类基数之和等于招生人次。业务新生只用于预算新生缺口，不用于替换退班分类起点。
- 同期退班：使用上一业务财年同季度过程与最终分子、分母；逐级回退时先汇总 N/D，再计算比例。每个分类的过程与最终必须同一层，新老生可以不同层。
- 剩余退班率：`MAX(0, 去年最终率 − 去年同期过程率)`。最小样本门槛默认 30，数据维护人员可版本化修改。
- 后续新增：校区 `MAX(0, 预算业务新生 − 当前累计业务新生)`，按明细正向新生缺口分配，不能提前扣退班。
- 取整：按校区与分类汇总后 `.5` 向上，明细采用稳定完整键的最大余数法，退班不得超基数。
- 尚未定版季度收入：人数终值乘完整季度继承参数，并计入正确的既有业务财季结转；不得用预算结转代替缺失的实际结转，也不得叠加当季重算收入和同课程过程实际。
- 已定版季度不可回退、不可手工覆盖冻结实际。实际修正只能新建来源快照及预测版本。

## 存储与 API

预测运行时只读取 PostgreSQL 的 `forecast_ledger_event`，不再依赖 `output/forecast-ledger`。每个版本完整保存当时的实际快照、预测参数、计算结果、调整原因和版本关系；确认作为独立追加记录保留。数据库禁止更新、删除历史事件，部门级事务锁、父版本检查与请求编号去重防止覆盖和重复生成。规范化原始字节与内容/前事件指纹用于核对数值精度和版本链。

已有文件历史通过 `scripts/import_forecast_ledger.py` 显式迁移，默认只检查；实际导入需 `--apply --actor <导入人> --reason <原因>`。导入前备份数据库及原文件，事务内逐事件核对，重复导入不新增、不覆盖；原版本 ID、快照指纹、参数、结果及确认状态均不重算。文件仅作为原始备份保留，数据库不可用时不能静默回退到文件。

每次“更新预测”先完成观远只读连接检查、完整抽取、前后分区/版本一致性验证，再计算并原子保存版本。新取数同时保留允许字段范围内的汇总宽表、财务明细业务行；归档时再次筛选字段，不保存 CLI 意外返回的学员姓名、手机号等身份字段。早期历史版本只保留当时实际已有的快照，不能补造当时没有保存的原始行。查询或计算失败不生成新版本；入库以事务防止部分写入，不覆盖最近一次成功预测。

网络中断、服务暂时不可用等瞬时故障最多自动重试 2 次，单次查询默认最多 60 秒，整轮取数默认最多 180 秒；取消和超时会终止、回收查询进程及其子进程。登录、权限、证书、响应格式和网络故障分别提示，后台只记录分类、阶段、次数、耗时和诊断编号，不保留凭据或错误输出中的业务数据。`BUDGET_GUANCLI_PROXY_URL` 可指定仅供观远连接使用的代理，本地 API/数据库绕过代理；不改系统代理，不关闭证书校验。

失败时“重试更新”重新执行同一更新请求，而不是读取旧结果；相同请求编号在已经成功保存的情况下返回原结果，避免重复生成。客户端等待上限为 200 秒，为后端 180 秒取数后的计算、保存、响应预留余量。若响应中断、无法判定是否已保存，明确提示结果尚未确认，再以原请求编号核对，不宣称一定未保存。页面保留最近一次成功版本的编号及数据日期。历史版本可只读打开并下载完整快照，下载包包含生成者、生成原因、父版本、基准类型和确认记录；浏览不调用 BI、不开 Excel、不重新计算，也不改变当前预测或 FY28 已冻结来源。

## 验收

- 冻结净收入没有二次税务转换；已冻结版本不随 BI 更新变化。
- 不匹配实际仍进入已定版部门合计，并明确阻断完整预测确认，不消失、不近似归并。
- 剩余历史退班字段逐完整维度勾稽、最小样本与回退通过；人工调整不能覆盖原历史率。
- 寒假、春季对秋季终值变化有连续响应，不复制未来定版预算金额。
- 数值缺失、负人数、不完整维度、超基数及无法完整抽取时不能伪造预测；UI 显示待处理，不显示虚假达成率。真实财务负调整仅在完整抽取、逐键与部门金额勾稽、分区稳定性和保存金额均验证通过时保留净额；未经核实的负财务值仍阻断。
- 刷新、调整、确认幂等；旧父版本操作拒绝；变更新版本不沿用确认。
- 历史试用完整不等于正式可确认；即使错误计算结果标记 ready，历史试用版本仍必须被存储层拒绝正式确认。固定规则草稿不再受试用身份阻断，但仍须通过真实数据检查，不能将规则生效等同于预测已确认。
- FY27 原表 SHA、收入和人数合计不变；FY28 R150 修订内容指纹不变。
- 构建、定向单元/API 测试和真实浏览器验证分别记录，真实数据尚未确认映射时不能声称正式全年预测已经完成。
